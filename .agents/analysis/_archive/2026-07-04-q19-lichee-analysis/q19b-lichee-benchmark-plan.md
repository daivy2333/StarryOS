# Q19B Lichee RV Dock Benchmark Bring-up Plan

> Part of StarryOS codebase analysis (branch: `uart-16550-lichee`)
> Generated by openspec-explorer at 2026-06-29
> Scope: planning the next Lichee RV Dock stage after Q19A smoke success, with the final goal of collecting async UART benchmark data on real D1 hardware.
> See also: [Lichee RV Dock bring-up notes](../../docs/licheerv-dock-bringup.md), [platform-parameter-decoupling](platform-parameter-decoupling.md), [d1-axplat-bringup-plan](d1-axplat-bringup-plan.md), [benchmark-report-async](../../docs/benchmark-report-async.md)

## 1. Goal

Q19A proved that StarryOS can be loaded by the official Lichee RV Dock U-Boot Android boot flow and can print:

```text
[starry-d1] early boot
[starry-d1] smoke complete, halting.
```

Q19B should extend that result to a benchmark-capable StarryOS environment on the same board. The end state is not merely "boot farther"; it is:

1. D1 uses the real async UART stack, not only polling early console.
2. `/dev/console` works through `Tty<AsyncUartReader, AsyncUartWriter>`.
3. The existing `tests/benchmark.c` or an equivalent benchmark payload runs under StarryOS.
4. The output can be copied directly from the serial terminal, like the current QEMU workflow.
5. Results are recorded separately from QEMU because QEMU does not model physical UART line delay.

The benchmark target is the same user-facing surface as QEMU:

```text
benchmark.c
  -> open("/dev/console")
  -> write + tcdrain
  -> O_NONBLOCK / FIONBIO read checks
  -> printf results to serial
```

## 2. Current State

### 2.1 What already works

| Area | Status | Evidence |
|------|--------|----------|
| Boot image format | Works | Android boot image `name = d1-nezha`, `kernel_addr = 0x40200000` |
| Link/load address | Works | D1 high-half `0xffffffc040200000`, physical load `0x40200000` |
| D1 axplat boot | Works | Board reaches StarryOS payload |
| Early console | Works | D1 UART0 32-bit polling output visible |
| C906 page-table attributes | Works for Q19A | early and final page table fixes got to smoke complete |
| Timer read path | Partially works | `time::read()` based time implementation exists; smoke printed boot timestamp |
| PLIC implementation | Code exists behind feature | `axplat-riscv64-lichee-d1` has `irq` feature with PLIC claim/complete |

### 2.2 What is intentionally disabled

Q19A had to disable full StarryOS userland features to isolate first boot:

| Disabled path | Why |
|---------------|-----|
| `entry.rs` normal init | `lichee-d1` branch calls `run_lichee_d1_smoke() -> !` |
| fs/net/display/axdriver | D1 has no virtio block/display/net yet |
| `task-ext` | Lichee smoke does not build Starry process extensions |
| real PLIC IRQ | top-level feature enables `irq-if`, not `axplat-riscv64-lichee-d1/irq` |
| async UART driver | current `uart_init` still assumes byte MMIO in raw probes and `uart_16550::MmioBackend` |
| user benchmark | no rootfs or init payload path is available in Q19A |

This split was correct for Q19A. Q19B must now add these capabilities back one at a time.

## 3. Benchmark Dependency Chain

The current QEMU benchmark path is:

```text
src/main.rs::main
  -> starry_kernel::entry::init(args, envs)
  -> uart_init::init_uart_hardware()
  -> drivers::bench::run_startup_benchmark()
  -> pseudofs::mount_all()
  -> load_user_app("/bin/sh", "-c", init.sh)
  -> add_stdio("/dev/console")
  -> spawn user task
  -> benchmark.c opens /dev/console
```

For Q19B, each node has a D1 blocker:

| Node | Current D1 blocker | Q19B action |
|------|--------------------|-------------|
| `entry::init` | `lichee-d1` cfg exits through smoke loop | Add staged Lichee modes: smoke, kernel-bench, async-console, user-bench |
| `init_uart_hardware` | raw LSR read uses `base+5` byte access; `uart_16550::MmioBackend` is U8 | Add D1/DW APB 32-bit UART port path or extend `uart_16550` backend |
| ISR registration | `LICHEE_D1.console.irq` is `None`; top-level feature only enables no-op irq stub | Enable D1 `irq` feature and set console IRQ 18 when testing async UART |
| `run_startup_benchmark` | depends on async driver instance | Use as first non-user benchmark gate after async UART init |
| `pseudofs::mount_all` | can mount devfs/tmpfs/proc, but full `axfs` root may still expect block device | Provide a no-block benchmark payload path before full rootfs |
| `load_user_app` | loads ELF from filesystem path | Either bring SDMMC/rootfs online or embed benchmark ELF in kernel for Q19B |
| `/dev/console` | depends on ASYNC_TTY and line discipline | Re-enable TTY after async UART IRQ works |
| `benchmark.c` | requires `clock_gettime`, `write`, `tcdrain`, `ioctl(FIONBIO)` | Preserve existing QEMU benchmark ABI; avoid board-specific test code unless necessary |

## 4. Recommended Strategy

### 4.1 Do not jump directly to SDMMC/rootfs

The final goal is user benchmark, but a full block driver is not the best next blocker. If Q19B starts by enabling SDMMC, rootfs, user process, async UART, PLIC, and benchmark together, failures will be hard to attribute.

The safer route is:

```text
polling boot
  -> real timer + scheduler sanity
  -> real PLIC external IRQ
  -> async UART kernel benchmark
  -> /dev/console TTY
  -> embedded user benchmark payload
  -> optional SDMMC/rootfs parity with QEMU
```

This still reaches the same final benchmark surface, but each stage has a clear serial log gate.

### 4.2 Prefer an embedded benchmark payload before SDMMC

QEMU uses `/bin/sh -c init.sh` from rootfs. Lichee does not yet have SDMMC/block support in StarryOS. To reach benchmark data sooner, Q19B should consider an intermediate "embedded init app" path:

1. Cross-compile `tests/benchmark.c` to a static RISC-V ELF.
2. Include it into the kernel image at build time or into a small initramfs-like blob.
3. Teach `load_user_app` or a Lichee-specific loader path to load that embedded ELF.
4. Keep `/dev/console` and syscalls identical to QEMU.

This avoids coupling benchmark bring-up to SDMMC. SDMMC/rootfs can remain a later parity milestone.

### 4.3 Keep kernel benchmark and user benchmark separate

`kernel/src/drivers/bench.rs` measures ring buffer speed and internal driver properties. It should be used as the first async UART gate on D1, but it is not a substitute for `tests/benchmark.c`.

| Benchmark | Purpose | Q19B role |
|-----------|---------|-----------|
| Kernel ring benchmark | Checks driver/ring/copy path; does not prove syscall/TTY/tcdrain | First async UART gate |
| User benchmark.c | Checks `/dev/console`, syscalls, tcdrain, FIONBIO, scheduler | Final Q19B gate |

## 5. Milestone Plan

### Q19B-M0: Mode split and artifact gates

Goal: make Lichee builds selectable by bring-up mode without editing code between tests.

Proposed modes:

| Mode | Behavior |
|------|----------|
| `lichee-smoke` | Current Q19A behavior: early console then halt |
| `lichee-kbench` | Boot StarryOS runtime, init async UART, run kernel benchmark, halt |
| `lichee-userbench` | Boot full enough user path to run benchmark payload |

Gate:

- `make lichee` or equivalent can produce a Q19A smoke image unchanged.
- New mode names are explicit in build output.
- Android boot image remains below boot partition size.

### Q19B-M1: D1 UART backend for async stack

Goal: make `uart_init::init_uart_hardware()` safe on D1.

Required changes:

- Stop using byte raw probe `base+5` for D1.
- Add a `UartPort` implementation for DW APB UART with stride 4 and 32-bit MMIO, or extend `uart_16550::MmioBackend` to support access width.
- Keep upper layers (`AsyncUartDriver`, `AsyncUartReader`, `AsyncUartWriter`, `Tty`) unaware of MMIO width.
- Preserve QEMU NS16550 U8 behavior.

Gate:

- Board prints UART register dump using D1-safe access.
- Kernel can create `AsyncUartDriver`.
- RX/TX copier tasks start without fault.

### Q19B-M2: Real PLIC/UART IRQ

Goal: prove UART0 IRQ 18 can wake the async driver.

Current useful code:

- `crates/axplat-riscv64-lichee-d1/src/irq.rs` already implements PLIC claim/complete behind feature `irq`.
- `axconfig.toml` already records `uart-irq = 18` and `plic-paddr = 0x1000_0000`.

Required changes:

- Enable `axplat-riscv64-lichee-d1/irq`, not only `irq-if`, for the IRQ test mode.
- Set `LICHEE_D1.console.irq = Some(18)` or otherwise expose IRQ 18 to `uart_init`.
- Add a minimal IRQ counter log before trusting TTY.

Gate:

- `axhal::irq::register_irq_hook(uart_isr_wrapper)` can register.
- PLIC external interrupt path claims source 18 and completes it.
- TX/RX wakers fire from interrupt, not polling-only.

### Q19B-M3: Kernel async UART benchmark

Goal: run `drivers::bench::run_startup_benchmark()` on D1 after async UART is initialized.

Gate:

- Serial log includes `[BENCH] Running startup benchmark...`.
- Ring buffer TX/RX numbers print.
- IRQ count is nonzero after deliberate UART traffic, or explicitly explained if the test only measures ring buffers.

This is the first performance data point, but still not the final QEMU-equivalent benchmark.

### Q19B-M4: `/dev/console` TTY without user process

Goal: prove the devfs/TTY object graph can be built on D1 before loading user ELF.

Required path:

```text
pseudofs::mount_all()
  -> dev::new_devfs()
  -> /dev/console backed by ASYNC_TTY
  -> add_stdio() can open /dev/console
```

Gate:

- `pseudofs::mount_all()` succeeds without requiring block rootfs.
- `/dev/console` write path reaches async UART.
- `tcdrain` equivalent path can observe transmitter empty.

### Q19B-M5: Embedded benchmark ELF

Goal: run the existing benchmark workload without SDMMC/rootfs.

Recommended route:

- Compile `tests/benchmark.c` with `riscv64-linux-musl-gcc -static`.
- Embed the resulting ELF into the kernel image for `lichee-userbench`.
- Reuse existing user ELF loader logic as much as possible.
- Keep benchmark code source-compatible with QEMU; only the delivery mechanism changes.

Gate:

- User process starts.
- `printf` reaches serial through fd 1 -> `/dev/console`.
- `open("/dev/console")`, `write`, `tcdrain`, `read`, `ioctl(FIONBIO)` execute.
- Output has the same sections as QEMU:
  - TX Throughput
  - TX Latency
  - FIFO Boundary Matrix
  - Non-blocking Read

### Q19B-M6: Optional SDMMC/rootfs parity

Goal: make Lichee run benchmark from a filesystem like QEMU.

This is optional for the first Q19B benchmark result. It becomes important when:

- multiple user programs must be deployed,
- benchmark binaries should be swapped without rebuilding the kernel,
- Lichee should behave like a normal StarryOS board target.

Gate:

- StarryOS mounts a real block-backed rootfs on D1.
- `/bin/benchmark` can be loaded from filesystem.
- Results match the embedded benchmark within expected variance.

## 6. Data Collection Format

Q19B result logs should be copied directly from the serial tool and stored under `.claude/analysis/lichee/`.

Recommended filename pattern:

```text
.claude/analysis/lichee/q19b-YYYYMMDD-{mode}.txt
```

Each result should record:

| Field | Example |
|-------|---------|
| Board | Lichee RV Dock / Allwinner D1 / C906 |
| Build mode | `release`, `DWARF=n` |
| StarryOS mode | `lichee-kbench` or `lichee-userbench` |
| UART | DW APB UART0, 115200, stride 4, width 32 |
| IRQ mode | polling / PLIC IRQ 18 |
| Payload source | embedded ELF / rootfs |
| Benchmark commit | git commit or working tree note |
| Raw serial output | full copied log |

Result tables in `docs/benchmark-report-async.md` should add a separate "Lichee D1" column instead of overwriting QEMU data.

## 7. Risks

| Risk | Symptom | Mitigation |
|------|---------|------------|
| DW APB UART is not fully 16550-compatible | THR/LSR/IIR behavior differs under IRQ | Start with D1-specific `UartPort`; only generalize after board data |
| PLIC setup incomplete | no UART IRQ, copier tasks stall | test IRQ counter before TTY |
| `task-ext`/process modules still gated off | user task link/runtime failure | make `lichee-userbench` re-enable only what user task needs |
| No block device | `No block device found!` | use embedded benchmark ELF before SDMMC |
| Final image grows again | boot partition write fails | keep `DWARF=n`; inspect image size every gate |
| Benchmark perturbs serial output | measurement bytes appear as terminal garbage | keep benchmark buffers zero-filled as in QEMU |
| QEMU comparison is misleading | D1 throughput much lower than QEMU | report D1 separately; QEMU does not model line delay |

## 8. Open Design Decisions

### Decision 1: Extend `uart_16550` or add D1-specific `UartPort`

For Q19B-M1, a local D1-specific `UartPort` is probably the fastest path because the async driver only needs:

- `receive_bytes`
- `send_bytes`
- `transmitter_empty`
- `update_ier`

Extending `uart_16550::MmioBackend` is better long-term because VisionFive2 also needs stride 4 / width 32. The pragmatic plan is:

1. Implement D1-specific path if it shortens board validation.
2. After D1 benchmark works, extract the width-aware backend into `uart_16550`.

### Decision 2: Embedded ELF vs SDMMC first

Embedded ELF is better for Q19B because it isolates benchmark execution from block driver bring-up. SDMMC/rootfs should be Q19C or a later Lichee milestone unless the user specifically wants filesystem parity first.

### Decision 3: How to name features

The current `lichee-d1` feature means "smoke-only" in practice. Q19B should avoid overloading it further. Prefer explicit features or app modes:

- `lichee-d1-smoke`
- `lichee-d1-kbench`
- `lichee-d1-userbench`

If Cargo feature sprawl becomes awkward, use one feature plus build-time env/app mode, but logs must still print the active mode.

## 9. Minimal Success Definition

Q19B is complete when a real Lichee RV Dock serial log contains:

```text
platform = riscv64-lichee-d1
[kernel] Async UART driver initialized
[BENCH] Startup benchmark complete
UART Async Benchmark
=== TX Throughput (to /dev/console + tcdrain) ===
=== TX Latency (single byte + tcdrain) ===
=== TX Latency FIFO Boundary Matrix ===
=== Non-blocking Read (FIONBIO) ===
Done.
```

The first Q19B completion can use an embedded benchmark payload. Full SDMMC/rootfs parity is valuable, but it should not block the first real D1 async UART benchmark dataset.
