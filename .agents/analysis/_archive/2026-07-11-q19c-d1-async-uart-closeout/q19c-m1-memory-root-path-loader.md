## 1. 目标与边界

Q19C-M1 的目标不是重新验证 UART 性能，也不是接入真实 SDMMC/rootfs。性能基线以 `docs/benchmark-report-async.md` 为准；M1 只证明 D1 可以通过 VFS path 解析和 file-backed ELF loader 运行 benchmark。

成功链路应从当前：

```text
init_memory_root()
  -> include_bytes!("../resources/benchmark.elf")
  -> load_embedded_user_app()
  -> Process::new_init()
  -> /dev/console stdio
  -> benchmark
```

推进到：

```text
init_memory_root()
  -> create /bin
  -> write /bin/benchmark
  -> mount_all()
  -> FS_CONTEXT.resolve("/bin/benchmark")
  -> load_user_app()
  -> Process::new_init()
  -> /dev/console stdio
  -> benchmark
```

明确不做：

- 不继续探究 D1 P99 长尾；ADR-053 已决定它不是 Q19C 主线阻塞项。
- 不把 memory-root 结果标记为真实 rootfs。
- 不调用 `axfs::init_filesystems()`；没有 block device 时该路径会 panic。
- 不让 Q19B `lichee-d1-userbench` 静默变成 fullbench。Q19B embedded 路径仍是回归基线。

## 2. 当前入口结构

`kernel/src/entry.rs` 已经把 QEMU 和 D1 分开：

| 路径 | feature | 当前行为 |
|------|---------|----------|
| QEMU | `not(feature = "lichee-d1")` | `pseudofs::mount_all()` 后从 `args[0]` resolve，再 `load_user_app()` |
| D1 smoke | `lichee-d1` 且非 async UART | polling early console smoke 后 halt |
| D1 kbench | `lichee-d1-async-uart` 且非 userbench | async UART 初始化 + startup benchmark 后 halt |
| D1 userbench | `lichee-d1-userbench` | memory root + devfs + embedded ELF + `load_embedded_user_app()` |

D1 userbench 已经具备 M1 需要的大部分外围流程：

- async UART 初始化：`uart_init::init_uart_hardware()`
- kernel startup benchmark：`bench::run_startup_benchmark()`
- memory root 初始化：`pseudofs::init_memory_root()`
- pseudo fs mount：`pseudofs::mount_all()`
- user address space：`new_user_aspace_empty()` + `copy_from_kernel()`
- process setup：`Process::new_init()` + `Thread::new()`
- console binding：`ASYNC_TTY.bind_to(&proc)`
- stdio：`file::add_stdio()` 打开 `/dev/console`
- spawn/join：`spawn_task()` + `task.join()`

M1 不应重写这些外围流程。最小改动点是替换“embedded ELF 载入”这一段。

## 3. 需要新增的模式

当前 `Cargo.toml` 已有：

```text
lichee-d1-userbench = [
  "lichee-d1-async-uart",
  "axfeat/paging",
  "starry-kernel/lichee-d1-userbench",
]
```

`kernel/Cargo.toml` 中 `lichee-d1-userbench` 进一步启用：

```text
["lichee-d1-async-uart", "dep:axfs", "axfeat/paging", "axfeat/task-ext"]
```

M1 应新增独立 fullbench mode，例如：

```text
root Cargo.toml:
lichee-d1-fullbench = [
  "lichee-d1-async-uart",
  "axfeat/paging",
  "starry-kernel/lichee-d1-fullbench",
]

kernel/Cargo.toml:
lichee-d1-fullbench = [
  "lichee-d1-async-uart",
  "dep:axfs",
  "axfeat/paging",
  "axfeat/task-ext",
]
```

这与 userbench 依赖集基本相同，但运行语义不同：

- `lichee-d1-userbench`: embedded payload regression，继续调用 `load_embedded_user_app()`
- `lichee-d1-fullbench`: M1 path-loader proof，必须调用 `load_user_app()`

Makefile 建议新增目标：

```text
lichee-fullbench-mem: kernel/resources/benchmark.elf
  APP_FEATURES=lichee-d1-fullbench
  DWARF=n
  output=starry-lichee-fullbench-mem-boot.img
```

同时新增 benchmark payload manifest，避免和 Q19B embedded 数据混写：

```text
BENCH_TARGET_MODE="lichee-d1-fullbench"
BENCH_STARTUP_CHAIN="android-boot-image -> memory-root /bin/benchmark -> load_user_app"
BENCH_ROOT_PROVIDER="d1-memory-root-path"
BENCH_D1_DIAG
```

## 4. Memory Root 注入方式

当前 `pseudofs::init_memory_root()` 只创建空 tmpfs root：

```rust
pub fn init_memory_root() {
    let fs = MemoryFs::new();
    let mp = Mountpoint::new_root(&fs);
    ROOT_FS_CONTEXT.call_once(|| FsContext::new(mp.root_location()));
}
```

`mount_all()` 会在当前 root 下挂载 `/dev`、`/dev/shm`、`/tmp`、`/proc`、`/sys`，不会覆盖 `/bin`。因此 M1 的顺序应是：

```rust
pseudofs::init_memory_root();

{
    let fs = FS_CONTEXT.lock();
    fs.create_dir("/bin", NodePermission::from_bits_truncate(0o755))?;
    fs.write("/bin/benchmark", include_bytes!("../resources/benchmark.elf"))?;
    fs.resolve("/bin/benchmark")?;
}

pseudofs::mount_all()?;
```

注意：`FsContext::write()` 当前已经存在于 `crates/axfs-ng/src/highlevel/fs.rs`，会通过 `File::create()` 创建或覆盖文件。M1 不需要新增 `MemoryFs` API，也不需要直接调用 tmpfs inode 的 `write_at()`。

### 关键约束

| 约束 | 原因 |
|------|------|
| `/bin` 必须在 `mount_all()` 前创建 | `mount_all()` 会创建其他挂载点，先注入可立即验证 root provider |
| 注入后必须 `resolve("/bin/benchmark")` | 明确 path-loader proof 入口存在，失败时早报错 |
| 使用 `FsContext::write()` | 当前 high-level API 已支持创建/覆盖文件，避免依赖 tmpfs 内部节点 |
| 不直接改 `MemoryFs`/`MemoryNode` | 这会扩大范围，也绕过 page cache/high-level path |
| benchmark 必须保持 static no-PIE / no relocation | 当前 loader 不处理 relocation；Q19B 已记录该约束 |

## 5. Loader 差异

`load_user_app()` 的关键行为：

1. path 来源：`path` 参数优先，否则 `args[0]`
2. 通过 `ELF_LOADER.lock().load(uspace, path)` 进入 file-backed ELF loader
3. `ElfLoader::load()` 内部调用 `FS_CONTEXT.lock().resolve(path)`
4. `ElfCacheEntry::load(loc)` 用 `CachedFile::get_or_create(loc)` 读取 ELF header 和 program headers
5. `map_elf()` 使用 `FileBackend::Cached(cache)` 建立用户段映射
6. 最后映射 user stack、写 argv/envp/auxv、建立 heap

`load_embedded_user_app()` 则直接从 `&[u8]` 解析和复制 ELF，不走 `FS_CONTEXT.resolve()`、`CachedFile` 或 file-backed mapping。因此，M1 的核心验证价值正是覆盖这些 Q19B 没覆盖的路径。

### 调用链

```text
entry::lichee_d1_init(fullbench)
  -> init_memory_root()
  -> FS_CONTEXT.create_dir("/bin")
  -> FS_CONTEXT.write("/bin/benchmark", benchmark bytes)
  -> FS_CONTEXT.resolve("/bin/benchmark")
  -> mount_all()
  -> new_user_aspace_empty()
  -> copy_from_kernel()
  -> load_user_app(uspace, Some("/bin/benchmark"), args, envs)
       -> ElfLoader::load()
       -> FS_CONTEXT.resolve("/bin/benchmark")
       -> CachedFile::get_or_create()
       -> map_elf(FileBackend::Cached)
  -> Process::new_init()
  -> ASYNC_TTY.bind_to()
  -> add_stdio()
  -> spawn_task()
  -> join()
```

## 6. 建议实现形态

建议在 `entry.rs` 中保持 Q19B userbench 分支不动，新增 fullbench 分支。可以把 user process 创建公共部分抽成一个小 helper，但不要为了 M1 做大规模重构。

推荐分层：

| 函数 | 作用 |
|------|------|
| `lichee_d1_init()` | 共用 D1 async UART 初始化和 kbench |
| `run_lichee_userbench_embedded()` | 保留 Q19B embedded regression |
| `run_lichee_fullbench_memory_root()` | M1 path-loader proof |
| `populate_memory_root_benchmark()` | 创建 `/bin/benchmark`，只做 VFS 注入 |
| `spawn_benchmark_process()` | 可选 helper，复用 process/stdio/spawn 逻辑 |

如果只做最小改动，可以先不抽 `spawn_benchmark_process()`，直接复制 Q19B userbench 中的进程创建代码；但必须保证 fullbench 分支调用的是 `load_user_app()`。

## 7. 验证 Gate

M1 不要求重新证明性能优于基线。验证重点是启动链路和功能：

| Gate | 期望 |
|------|------|
| host build | `make lichee-fullbench-mem` 生成 Android boot image |
| image inspect | 输出 `starry-lichee-fullbench-mem-boot.img`，保留 `DWARF=n` |
| boot log | 明确打印 `target_mode=lichee-d1-fullbench` / `root_provider=d1-memory-root-path` |
| path proof | 明确打印 `/bin/benchmark` resolve 成功，且 fullbench 不调用 `load_embedded_user_app()` |
| benchmark | 出现 manifest、S10/S20/S21/S30 等 sections，最终 exit code 0 |
| regression | `make lichee-userbench` 仍代表 embedded path，不被 fullbench 替换 |

失败时建议输出阶段化错误：

```text
[starry-d1] fullbench: init memory root
[starry-d1] fullbench: populate /bin/benchmark
[starry-d1] fullbench: resolve /bin/benchmark ok
[starry-d1] fullbench: mount pseudofs
[starry-d1] fullbench: load_user_app /bin/benchmark
[starry-d1] fullbench: benchmark process spawned
```

## 8. 风险点

| 风险 | 触发 | 处理 |
|------|------|------|
| feature 混淆 | fullbench 继承 userbench 或复用 `qemu` | fullbench 独立 feature，只继承 D1 async UART/paging/task-ext/axfs |
| payload 仍是 embedded proof | 日志看似成功但走 `load_embedded_user_app()` | fullbench 分支禁止调用 embedded loader |
| `/dev/console` 不存在 | `add_stdio()` 打开失败 | 必须先 `mount_all()`，确保 devfs 绑定 console |
| `/bin/benchmark` 被覆盖 | 错误 mount root 或重建 root | 只在 memory root 初始化后注入，`mount_all()` 不挂 `/bin` |
| dynamic ELF | `PT_INTERP` 需要动态 linker | 继续用 `-static -no-pie -fno-pie -s`，验证无 `INTERP` / relocation |
| rootfs 误入 | 调用 `init_filesystems(empty)` | M1 不碰 block/rootfs 初始化 |
