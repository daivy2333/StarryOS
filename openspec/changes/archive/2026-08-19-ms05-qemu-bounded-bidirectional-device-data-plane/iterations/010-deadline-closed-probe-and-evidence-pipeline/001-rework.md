**Critical Path**

```text
fresh clock and positive remaining budget
  -> install a timeout bounded to that budget
  -> prove positive budget at the actual blocking I/O boundary
  -> send/receive/nonblocking nudge
  -> postcheck equal/late/regressed return
  -> no later operational side effect on failure

source files + HEAD + index/worktree identity captured before Gates
  -> one capture path records literal argv/result/raw log
  -> artifact record names its actual producing Gate
  -> audit verifies time/order/identity/producer
  -> R44 accepts only the earliest unambiguous capability failure
```

**Implementation Guidance**

Keep deadline sequencing inside the existing test-tool operation seam. Make
the fake timeout/nonblock/I/O operations independently advance the clock so
tests observe the boundary rather than call-count assumptions. Distinguish
best-effort resource restoration from operational send/receive work: cleanup
may report failure, but it cannot authorize new payload progress.

Use a single internal capture result shape for normal, D1, repeated and
artifact subprocesses so timeout, argv, raw log and classification cannot
drift between paths. Represent index/worktree identity with read-only Git
output and hash it; fixtures must use temporary repositories or temporary
manifest copies and must not mutate the live index or worktree.

**Behavioral Change**

- A timeout setter or nonblocking transition that reaches the deadline
  prevents the following send/receive from starting.
- Guest and Python receives reject equal/late returns before parsing data or
  starting another side effect; host sends use a timeout no larger than the
  current exchange remainder.
- Source freeze includes auditable index/worktree identity and temporal order.
- Artifact records identify the actual generating Gate.
- R44 accepts a capability block only when it is the earliest unambiguous
  failing layer; an earlier product failure remains a product failure.
