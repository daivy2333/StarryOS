
### Terminal B — QEMU (serial recorded to file)

```bash
cd /home/daivy/projects/serial/work/StarryOS
EV=openspec/changes/ms05-qemu-bounded-bidirectional-device-data-plane/evidence/011-independent-manual-qemu-runtime-and-closeout/000-initial
script -q -f "$EV/qemu-serial.log" -c \
'qemu-system-riscv64 -machine virt -bios default -kernel StarryOS_riscv64-qemu-virt.bin -m 1G -smp 1 -device virtio-blk-device,drive=disk0 -drive id=disk0,if=none,format=raw,file=make/disk.img -device virtio-net-device,netdev=net0 -netdev user,id=net0,hostfwd=tcp::5555-:5555,hostfwd=udp::5555-:5555 -nographic'
```

### Terminal C — per-mode host stimulus (start fresh before EACH mode)

```bash
cd /home/daivy/projects/serial/work/StarryOS
EV=openspec/changes/ms05-qemu-bounded-bidirectional-device-data-plane/evidence/011-independent-manual-qemu-runtime-and-closeout/000-initial
python3 scripts/ms05_data_plane_stimulus.py --host 0.0.0.0 --port 15557 | tee "$EV/ms05-<mode>-host.log"
```

### Guest (Terminal B shell, one command at a time at `starry:~#`)

First download the probe:

```sh
wget -q -O /tmp/ms05_probe http://10.0.2.2:18765/ms05_data_plane_probe
chmod +x /tmp/ms05_probe
```

Then for EACH mode: (1) start the matching host stimulus in Terminal C, (2) run
the guest command, (3) wait for the host stimulus to finish, (4) record the
guest exit status in `runtime-exits.txt`.

| Mode | Guest command | Host stimulus log |
|---|---|---|
| snapshot | `/tmp/ms05_probe snapshot` | `ms05-snapshot-host.log` |
| tx-only | `/tmp/ms05_probe tx-only 96 64` | `ms05-txonly-host.log` |
| bidirectional | `/tmp/ms05_probe bidirectional 96 64` | `ms05-bidirectional-host.log` |
| slot-full | `/tmp/ms05_probe slot-full` | `ms05-slotfull-host.log` |
| descriptor-full | `/tmp/ms05_probe descriptor-full` | `ms05-descfull-host.log` |
| flush | `/tmp/ms05_probe flush` | `ms05-flush-host.log` |

Each mode requires: exactly one `MS05 PASS mode=<mode>` terminal marker,
expected exact traffic counts (96×64 for tx-only/bidirectional), slot/ticket/
buffer/descriptor conservation, Full→recovery (slot-full/descriptor-full), C4
flush closure (flush), bounded work/yield telemetry, and zero fault/restore/IRQ
entry errors. A timeout, interrupted log, partial telemetry or one successful
mode cannot substitute for another.
