
```bash

script -q -f "$EV/qemu-wget-serial.log" -c \
'qemu-system-riscv64 -machine virt -bios default -kernel StarryOS_riscv64-qemu-virt.bin -m 1G -smp 1 -device virtio-blk-device,drive=disk0 -drive id=disk0,if=none,format=raw,file=make/disk.img -device virtio-net-device,netdev=net0 -netdev user,id=net0,hostfwd=tcp::5555-:5555,hostfwd=udp::5555-:5555 -nographic'
```

Terminal C — packet capture for this session (fresh pcap, never append):


Guest (Terminal B shell):

```sh

/tmp/ms01_test
```

- Smoke GREEN (all four required):
  1. guest command exits 0 with the 14 `PASS:` markers, no `FAIL:`;
  2. pcap order is ARP request/reply -> SYN/SYN-ACK/ACK -> HTTP request/response;
  3. no manual nudge or host injection was used;
  4. frozen hashes still verify (6/6 OK).
- If the wget/HTTP exchange stalls with no SYN after ARP or relies on any
  manual/software nudge, the smoke FAILS — capture the synchronized serial+pcap
  and return to Act/Plan. Do NOT proceed to the mode matrix.
- Use a fresh pcap file; append nothing to Cycle 000's `ms05-diag.pcap`.

### Session 1 — guest-only MS05 snapshot (NO host stimulus)

With the QEMU session from the smoke still booted (or a fresh identical boot),
guest-only:

```sh
wget -q -O /tmp/ms05_probe http://10.0.2.2:18765/ms05_data_plane_probe
chmod +x /tmp/ms05_probe
/tmp/ms05_probe snapshot
```

Record the marker and exit. `run_snapshot()` performs bounded diagnostic
snapshots only and never sends `MS05 REGISTER`; NO host stimulus is started for
this mode and NO `ms05-snapshot-host.log` is required. Save this as
`qemu-ms05-serial.log` (or keep session serials distinct per contract).

### Session 2 — five host-assisted modes (fresh host stimulus BEFORE each mode)

Keep the QEMU serial recording into `qemu-ms05-serial.log`. For each mode:
(1) start a fresh stimulus process in a separate terminal, (2) run the guest
command, (3) wait for the stimulus to finish, (4) record guest exit. The host
stimulus binds externally to the QEMU user-net; it does not require a hostfwd.

| Mode | Guest command | Host stimulus (start fresh, `tee` to the named file) |
|---|---|---|
| tx-only | `/tmp/ms05_probe tx-only 96 64` | `python3 scripts/ms05_data_plane_stimulus.py --host 0.0.0.0 --port 15557 \| tee "$EV/ms05-txonly-host.log"` |
| bidirectional | `/tmp/ms05_probe bidirectional 96 64` | `python3 scripts/ms05_data_plane_stimulus.py --host 0.0.0.0 --port 15557 \| tee "$EV/ms05-bidirectional-host.log"` |
| slot-full | `/tmp/ms05_probe slot-full` | `python3 scripts/ms05_data_plane_stimulus.py --host 0.0.0.0 --port 15557 \| tee "$EV/ms05-slotfull-host.log"` |
| descriptor-full | `/tmp/ms05_probe descriptor-full` | `python3 scripts/ms05_data_plane_stimulus.py --host 0.0.0.0 --port 15557 \| tee "$EV/ms05-descfull-host.log"` |
| flush | `/tmp/ms05_probe flush` | `python3 scripts/ms05_data_plane_stimulus.py --host 0.0.0.0 --port 15557 \| tee "$EV/ms05-flush-host.log"` |

Each mode requires exactly one `MS05 PASS mode=<mode>` marker, the expected
exact traffic counts (96×64 for tx-only/bidirectional), slot/ticket/buffer/
descriptor conservation, Full->recovery (slot-full/descriptor-full), C4 flush
closure (flush), bounded work/yield telemetry, and zero fault/restore/IRQ-entry
errors, all within the fixed absolute deadline. A timeout, interrupted log,
partial telemetry or one successful mode cannot substitute for another.
