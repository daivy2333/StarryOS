# MS09 Iteration 002 / 3.3 板上首字节采集 — CoM260 Kit 真板记录

环境: 2026-10-01；串口终端（host 侧，115200 8N1 无流控）；进入 U-Boot Shell 手法=板子启动时串口长按 `s` 键（SpacemiT 定制入口，官方文档交叉验证 + 本板确认有效）；装载路线=B1 U 盘（FAT32 整盘，`fatload usb 0:0`）；FIT=`StarryOS_riscv64-k3.fit`（276,000 B，`make k3` 产物，kernel load/entry 0x180000000、FDT load 0x181000000）。

## 2. 观察备注

- 进入手法：长按 `s` 在本板有效（`Autoboot in 0 seconds` 与其不矛盾——s 键为 SpacemiT 定制早期 console 入口，不走标准 autoboot 打断路径）。Iteration 001 遗留「控制台进入手法」未裁决项闭合。
- `kernel_addr_r=0x140000000`（落入 CMA `0x140000000–0x160000000`，禁作装载地址）——佐证本次 staging `0x2e0000000` 的选择。
- U-Boot lmb `reserved[4]=[0x2fbd7c000, 0x2ffffffff]`：观测到的 U-Boot 自占区起点高于本 change 裁决窗口上界 `0x2f0000000`——Iteration 001「U-Boot 自占边界」豁免项的现场佐证补齐（部分闭合）。
- FDT 重定位观察：bootm 将 FDT 从 `0x181000000` 重定位到 `0x2fbd4f000`（`fdt_high` 未定义时的默认行为）；重定位址高于裁决窗口、在 U-Boot 自占区一带。内核以 a1 接收该指针。
- 首字节链路判定：`[k3:pt-mmu]` 出现 → U-Boot 跳转、K3 Sv39 引导页表、MMU、UART0 clock/pinmux/MMIO 全部工作；axruntime 横幅与平台信息（riscv64-k3 / smp=1）输出 → 平台 crate 装配正确。
- panic 定位：`axallocator` 位图页分配器容量 CAP=1,048,576 页（4 GiB，`page-alloc-4g`）< 声明窗口 5.75 GiB（`phys_ram_range` 起点 `0xffffffc180082000`、`size=0x16ff7e000`）。修复方向：k3 构建启用 `axfeat/page-alloc-64g`（BitAlloc16M，64 GiB CAP；axallocator cfg 链 64g 优先于 4g，与其他平台无交互）。
- RTC 无电池（Boot 时刻 1970-01-01 起）与 Iteration 001 Minor 一致。
