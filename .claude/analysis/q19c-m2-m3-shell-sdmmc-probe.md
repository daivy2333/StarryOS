> See also: [q19c-lichee-full-starryos-benchmark](q19c-lichee-full-starryos-benchmark.md), [q19c-m1-memory-root-path-loader](q19c-m1-memory-root-path-loader.md)

## 1. 当前结论

M2 和 M3 可以一起推进，但应保持两个独立 gate。

M2 不应等待可用 `/bin/sh`。当前仓库没有可嵌入的静态 shell，`load_user_app()` 对脚本会转成 `/bin/sh`，并且源码已有 `/proc/self/exe` 的 busybox FIXME。M2 的低风险路线是先做 documented equivalent command entry：仍从 memory-root 解析 `/bin/benchmark`，但用独立 mode label、argv/envp、stdio、exit/join 证据覆盖 shell/script 入口要求。

M3 不应启用 rootfs 初始化。当前 D1 平台没有已注册的 SDMMC `AxBlockDevice`，`axfs-ng::init_filesystems()` 会在空 block list 上触发 `No block device found!`。M3 应先做 probe-only：打印已知 D1 分区事实、MMIO/clock/reset/pinmux/card-detect 待验证项，并输出 `SKIPPED: missing D1 SDMMC/block driver`。

## 2. M2 shell/script 路径

QEMU 的入口来自 `src/main.rs:9`：

```text
["/bin/sh", "-c", include_str!("init.sh")]
```

D1 M1 入口位于 `kernel/src/entry.rs:239` 之后。它已完成：

```text
pseudofs::init_memory_root()
  -> FS_CONTEXT.create_dir("/bin")
  -> FS_CONTEXT.write("/bin/benchmark")
  -> FS_CONTEXT.resolve("/bin/benchmark")
  -> pseudofs::mount_all()
  -> load_user_app_eager_from_path()
  -> Process::new_init()
  -> ASYNC_TTY.bind_to()
  -> add_stdio()
  -> spawn_task()
  -> join()
```

M2 要补的不是 VFS/path proof，而是“命令入口语义”：

| 项目 | 当前 M1 | M2 等价入口要求 |
|------|---------|----------------|
| mode label | `lichee-memory-root-path` | `lichee-memory-root-shell` 或 `lichee-memory-root-command` |
| argv | `["/bin/benchmark"]` | 记录等价命令，例如 `["/bin/benchmark", "--q19c-m2-command-entry"]` |
| envp | 空 | 显式记录 envp，可继续为空 |
| stdio | `/dev/console` | 必须保持 `/dev/console` |
| exit/join | 已 join benchmark | 必须记录 spawned + joined + exit code |
| shell 依赖 | 无 | 若 `/bin/sh` 不存在，记录 SKIPPED，不伪造 shell success |

### 推荐顺序

1. 新增 M2 mode label，不复用 M1 的 `lichee-memory-root-path`。
2. 仍注入 `/bin/benchmark` 和 `/init.sh` 文本文件。
3. 如果没有静态 `/bin/sh`，不要调用 `load_user_app("/init.sh")`。
4. 运行 documented equivalent command entry。
5. 串口日志记录：

```text
[starry-d1] log_label=lichee-memory-root-command
[starry-d1] shell_status=SKIPPED: no known-good static /bin/sh
[starry-d1] equivalent_entry=/bin/benchmark
[starry-d1] argv=/bin/benchmark,--q19c-m2-command-entry
[starry-d1] envp_count=0
[starry-d1] stdio=/dev/console
[starry-d1] benchmark exited with code: 0
```

如果后续有静态 shell，再升级为：

```text
/bin/sh -c /init.sh
```

此时需要额外验证 `/bin/sh` 是否依赖动态解释器、共享库和 `/proc/self/exe`。

## 3. M2 风险

`load_user_app()` 对 `.sh` 做了脚本重定向：遇到 `path.ends_with(".sh")` 时把参数改为 `/bin/sh`。如果 memory-root 没有 `/bin/sh`，它会失败在 shell resolve/load 阶段。

ELF fallback 也支持 shebang。读取到非 ELF 且以 `#!` 开头时，会解析解释器行并再次调用 `load_user_app()`。这适合未来 shell proof，但当前仍需要解释器实际存在。

因此 M2 文档化等价入口必须避免两种误判：

| 误判 | 处理 |
|------|------|
| kernel-launched benchmark 被当成 shell success | label 写成 command/equivalent，不写 shell success |
| `/init.sh` 缺 `/bin/sh` 被当成 benchmark failure | 输出 missing `/bin/sh` 和 loader stage |

## 4. M3 SDMMC/block probe

D1 真板事实已在旧采集中确认：

| 项目 | 已知事实 |
|------|----------|
| rootfs | `/dev/mmcblk0p7` ext4 |
| boot-resource | `/dev/mmcblk0p1` vfat |
| boot image | `/dev/mmcblk0p4` Android boot image |
| U-Boot 启动 | `sunxi_flash read 45000000 boot; bootm 45000000` |

当前 StarryOS 侧事实：

| 项目 | 当前状态 |
|------|----------|
| D1 axplat MMIO ranges | 只列 UART0 和 PLIC，未列 SDMMC |
| `virtio-mmio-ranges` | 空数组，D1 不能走 QEMU virtio block |
| `axfs-ng::init_filesystems()` | 对 block list 执行 `take_one().expect("No block device found!")` |
| `axdriver` MMIO bus | 只枚举 `VIRTIO_MMIO_RANGES`，不自动探测 D1 SDMMC |
| `simple-sdmmc` | 本地 registry 有通用 SD/MMC PIO/DMA 库，但未接入 D1 `AxBlockDevice` |

M3 的第一阶段不应构造 rootfs。应只采集 probe 表：

| Probe 项 | 证据 |
|----------|------|
| controller base | 待从 D1 manual/DTS 确认，不能猜 |
| MMIO access | 读 `ctrl/pwren/clkdiv/clkena/ctype/cdetect/verid/hcon` 或等价寄存器 |
| clock/reset | 记录是否继承 U-Boot，若不可继承列出 StarryOS 初始化缺口 |
| pinmux | 记录是否继承 U-Boot，若不可继承列出 GPIO/pin controller 缺口 |
| card detect | `cdetect` 或等价状态 |
| transfer mode | `probe-only` / `PIO-first`，明确 DMA 未进入 gate |
| first block read | 没有驱动时记录 SKIPPED；有 PIO prototype 时读 LBA0 |
| block registration | 未注册 `AxBlockDevice` 时禁止调用 `init_filesystems()` |

## 5. M3 推荐形态

先新增 rootfs-probe mode，而不是 rootfs mode。

```text
lichee-rootfs-probe
  -> print D1 known partition facts
  -> print SDMMC driver status
  -> if no D1 AxBlockDevice:
       SKIPPED: missing D1 SDMMC/block driver
       halt
  -> if block device exists:
       print device name
       only then consider axfs-ng::init_filesystems(block_devs)
```

如果要做只读寄存器 probe，应把实现放在 D1 平台或 kernel platform helper 中，保持以下限制：

- 不写 boot 分区。
- 不 mount `/dev/mmcblk0p4`。
- 不启用 QEMU `qemu` feature。
- 不调用 `init_filesystems()` 直到 `block_devs.len() > 0`。
- 不把 probe-only 失败归因到 UART、TTY、syscall 或 loader。
