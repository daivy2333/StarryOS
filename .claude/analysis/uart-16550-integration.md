## 1. uart_16550 Crate 基础架构

### 1.1 依赖声明

`uart_16550` 以本地 path 依赖方式引入 StarryOS 内核：

```toml
# kernel/Cargo.toml:105
uart_16550 = { path = "../../uart_16550" }
```

源 crate 位于 `../uart_16550/`，版本 0.6.0，edition 2024，上游仓库为 [rust-osdev/uart_16550](https://github.com/rust-osdev/uart_16550)。StarryOS 仅使用其 `MmioBackend` 变体（RISC-V 平台无 x86 Port I/O），且完全不依赖可选的 `embedded-io` feature。

### 1.2 核心类型体系

```
Backend (trait, sealed)
├── MmioBackend   ← StarryOS 唯一使用
│   ├── base_address: MmioAddress (NonNull<u8>)
│   └── stride: NonZeroU8
└── PioBackend    ← x86 only，未使用

Uart16550<B: Backend>
├── backend: B
├── base_address: B::Address
└── config: Config
```

**Backend trait**（`src/backend/mod.rs:53-151`）定义 MMIO 抽象的核心原语：

| 方法 | 签名 | 语义 |
|------|------|------|
| `read` | `unsafe fn(&mut self, offset: u8) -> u8` | 读指定偏移寄存器，内部执行 `offset * stride` 地址计算 |
| `write` | `unsafe fn(&mut self, offset: u8, value: u8)` | 写指定偏移寄存器，同样 stride 缩放 |
| `_read_register` | `unsafe fn(&mut self, addr: Self::Address) -> u8` | 底层 MMIO 读原语（`arch::mmio_read_register`） |
| `_write_register` | `unsafe fn(&mut self, addr: Self::Address, value: u8)` | 底层 MMIO 写原语（`arch::mmio_write_register`） |

`read`/`write` 为 `#[inline(always)]`，所有热点路径中 stride 乘法可被编译器常量折叠（stride 以 `NonZeroU8` 传入，编译期已知）。

### 1.3 NS16550 寄存器模型

uart_16550 的 `spec::offsets` 模块定义 8 个寄存器的逻辑偏移（`src/spec.rs:179-219`）：

| 寄存器 | 偏移 | 访问 | StarryOS 使用 |
|--------|:---:|------|:------------:|
| DATA (THR/RBR) | 0 | R/W | RX copier `receive_bytes()`, TX copier `send_bytes()` |
| IER | 1 | R/W | `ier()` / `set_ier()` — 中断使能控制 |
| ISR (读) / FCR (写) | 2 | R/W | `isr()` — ISR 中断类型判定 |
| LCR | 3 | R/W | 行控制（波特率配置时 DLAB bit） |
| MCR | 4 | R/W | 调制解调器控制（loopback 测试） |
| LSR | 5 | R | `lsr()` — 发送/接收状态 |
| MSR | 6 | R | 调制解调器状态 |
| SPR | 7 | R/W | 暂存寄存器 |

**关键常量**：`FIFO_SIZE = 16`（硬件 FIFO 深度），`NUM_REGISTERS = 8`，`CLK_FREQUENCY_HZ = 1_843_200`。

### 1.4 StarryOS 直接调用的 Uart16550 API

| API | 签名 | 调用位置 | 频率 |
|-----|------|----------|:---:|
| `new_mmio` | `unsafe fn(NonNull<u8>, stride: u8) -> Result<Self, ...>` | `uart_init.rs:46`（`lazy_static!` 初始化） | 1× |
| `ier()` | `fn(&mut self) -> IER` | `log_uart_state()` 调试输出 | 低 |
| `set_ier()` | `fn(&mut self, ier: IER)` | `write_ier()` → 所有 IER 修改路径 | 高频 |
| `isr()` | `fn(&mut self) -> ISR` | `log_uart_state()` | 低 |
| `lsr()` | `fn(&mut self) -> LSR` | `log_uart_state()`, `ctl.rs` tcdrain | 低 |
| `receive_bytes()` | `fn(&mut self, &mut [u8]) -> usize` | `rx_copier_loop` 主循环 | 极高 |
| `send_bytes()` | `fn(&mut self, &[u8]) -> usize` | `tx_copier_loop` 主循环 | 极高 |

> **Q8 增量**：`set_ier()` 为 Q8.3 阶段向 uart_16550 新增的公共 API（原 crate 仅暴露 `ier()` 读接口），替代了原先 `uart_init.rs` 中的裸 `write_volatile` 操作。

### 1.5 MmioBackend 初始化细节

```rust
// uart_init.rs:44-51 (lazy_static! 展开)
let base_address = NonNull::new(get_uart_mmio_virt().as_mut_ptr()).unwrap();
let uart = unsafe {
    Uart16550::new_mmio(base_address, /* stride */ 1).unwrap()
};
```

- `UART_MMIO_BASE_PHYS = 0x10000000`（RISC-V QEMU virt 平台 NS16550 基址）
- `get_uart_mmio_virt()` 通过 `phys_to_virt()` 转换为内核虚拟地址
- **stride MUST = 1**：NS16550 为字节寻址设备，8 个寄存器仅占 `0x00-0x07`。stride=4 会导致地址越界产生 LoadFault（参见 learned L122）

## 2. StarryOS 内核封装层

StarryOS 在 `kernel/src/drivers/` 目录下构建了六层封装，逐级抽象 uart_16550 的裸 API。

### 2.1 全局实例与锁策略 (`uart_init.rs`)

```
UART: lazy_static! { SpinNoIrq<Uart16550<MmioBackend>> }
```

- 使用 `SpinNoIrq`（关中断自旋锁）保护 `Uart16550` 实例，确保 copier 任务与初始化代码间的互斥
- `uart_instance()` 返回 `&'static SpinNoIrq<Uart16550<MmioBackend>>`，所有调用方通过 `.lock()` 获取 `&mut Uart16550`
- **ISR 绕过该锁**：`read_isr_unlocked()` 直接执行 `ptr.add(offsets::ISR).read_volatile()`，因 ISR 为单 handler 无并发竞争（Q8.2 去锁化）

### 2.2 IER 缓存与原子中断控制 (`uart_init.rs:82-92`)

```rust
static CACHED_IER: AtomicU8 = AtomicU8::new(0);

fn write_ier(value: u8) {
    CACHED_IER.store(value, Ordering::Relaxed);
    uart_instance().lock().set_ier(IER::from_bits_truncate(value));
}

pub fn enable_rx_intr()   { write_ier(CACHED_IER.load(Relaxed) | IER::DATA_READY.bits()); }
pub fn disable_rx_intr()  { write_ier(CACHED_IER.load(Relaxed) & !IER::DATA_READY.bits()); }
pub fn enable_tx_intr()   { write_ier(CACHED_IER.load(Relaxed) | IER::THR_EMPTY.bits()); }
pub fn disable_tx_intr()  { write_ier(CACHED_IER.load(Relaxed) & !IER::THR_EMPTY.bits()); }
```

**设计要点**：
- `CACHED_IER` 用 `AtomicU8` + `Relaxed` 顺序缓存当前 IER 值，避免 RMW 读硬件寄存器（~100-200ns MMIO 延迟）
- 四个 enable/disable 函数通过位操作修改缓存值后调用 `write_ier()` 一次性写入硬件
- 所有操作通过 `set_ier()` 走 uart_16550 安全 API（Q8.3 规范化），不再有裸 `write_volatile`

### 2.3 中断服务例程 (`isr.rs`)

```rust
pub static RX_WAKER:    AtomicWaker = AtomicWaker::new();
pub static TX_WAKER:    AtomicWaker = AtomicWaker::new();
pub static DRAIN_WAKER: AtomicWaker = AtomicWaker::new();
pub static TCDRAIN_ACTIVE: AtomicBool = AtomicBool::new(false);

pub fn uart_isr_handler(_irq: usize) {
    let isr = read_isr_unlocked();          // ① 无锁读 ISR
    match isr.interrupt_type() {
        Some(ReceivedDataReady) | Some(ReceptionTimeout) => {
            disable_rx_intr();              // ② 禁用 RX 中断
            RX_WAKER.wake();                // ③ 唤醒 RX copier
        }
        Some(TransmitterHoldingRegisterEmpty) => {
            disable_tx_intr();              // ② 禁用 TX 中断
            TX_WAKER.wake();                // ③ 唤醒 TX copier
            if TCDRAIN_ACTIVE.load(Acquire) {
                DRAIN_WAKER.wake();         // ④ 条件唤醒 tcdrain
            }
        }
        _ => {}
    }
}
```

**ISR 极简原则**：全程无锁、无数据搬运、无阻塞操作。仅执行 (1) 读 ISR → (2) 禁中断 → (3) AtomicWaker::wake() → (4) 返回，总延迟 ~1.5 µs。

**AtomicWaker 选择**：使用 `embassy_sync::AtomicWaker`（单槽唤醒）而非 `PollSet`（BTreeMap 分发），ISR 中 O(1) 唤醒。三个独立 waker 按中断类型分发：
- `RX_WAKER` → RX copier 的 `poll_fn`
- `TX_WAKER` → TX copier 的 `poll_fn`
- `DRAIN_WAKER` → tcdrain 等待者（Q8.5 条件化：仅 `TCDRAIN_ACTIVE` 时 wake）

### 2.4 环形缓冲区 (`ring_buffer.rs`)

```rust
pub const BUF_SIZE: usize = 64 * 1024; // 64 KB

pub struct RingBufRx { pub buf: HeapRb<u8>, pub poll: PollSet }
pub struct RingBufTx { pub buf: HeapRb<u8>, pub poll: PollSet }
```

基于 `ringbuf::HeapRb<u8>`（lock-free SPSC 环形缓冲区），封装为 RX/TX 双缓冲：

| 操作 | 行为 | 唤醒语义 |
|------|------|----------|
| `RingBufRx::push(data)` | `buf.push_slice(data)` → 若写入 >0 → `poll.wake()` | 通知 tty-reader 和用户态 read() |
| `RingBufRx::pop(buf)` | `buf.pop_slice(buf)` | — |
| `RingBufTx::push(data)` | `buf.push_slice(data)` | — |
| `RingBufTx::pop(buf)` | `buf.pop_slice(buf)` → 若读出 >0 → `poll.wake()` | 通知 TX copier 有数据待发送 |
| `RingBufTx::register_waker(cx)` | 若 `vacant_len > 0` → 立即 wake_by_ref；否则 `poll.register(cx.waker())` | 写者等待缓冲区空间 |

**锁策略**：`RingBufRx`/`RingBufTx` 本身无内部锁（`HeapRb` 为 SPSC），由外层 `Mutex` 保护并发访问。

## 3. 异步驱动 Copier 架构

### 3.1 全局驱动实例

```rust
lazy_static! {
    pub static ref DRIVER: Arc<AsyncUartDriver> = AsyncUartDriver::new();
}

pub struct AsyncUartDriver {
    pub rx: Mutex<RingBufRx>,  // RX 环形缓冲区（消费者：tty-reader / 用户态 read()）
    pub tx: Mutex<RingBufTx>,  // TX 环形缓冲区（生产者：用户态 write() / tty output）
}
```

`Mutex` 为 `axsync::Mutex`（基于内核自旋锁），保护每个 ring buffer 的并发 push/pop。

### 3.2 RX Copier 循环

```
┌─────────────────────────────────────────────────────────┐
│ rx_copier_loop (task: "uart-rx-copier")                  │
│                                                          │
│  poll_fn(|cx| {                                          │
│   ① uart = uart_instance().lock()                        │
│   ② total = uart.receive_bytes(&mut read_buf[..batch])   │
│   ③ drop(uart)                                           │
│   ④ if total > 0 { self.rx.lock().push(&read_buf[..total]) }│
│   ⑤ NAPI state machine:                                  │
│      if consecutive >= THRESHOLD {                       │
│        if total > 0 { consecutive++ }                    │
│        else { consecutive=0; enable_rx_intr() }  ← Q8.1  │
│      } else {                                            │
│        consecutive = if total>0 {+1} else {0}            │
│      }                                                   │
│      if consecutive < THRESHOLD { enable_rx_intr() }     │
│   ⑥ Waker dedup: will_wake check → RX_WAKER.register()  │
│   ⑦ Ready(total) if data, Pending otherwise              │
│  })                                                      │
└─────────────────────────────────────────────────────────┘
```

**NAPI 中断合并**（Q5 O2/O34，Q8.1 修复退出条件）：
- `NAPI_THRESHOLD = 16`：连续成功 ≥16 次后进入轮询模式
- 轮询模式下 batch=64（NAPI_BATCH_SIZE），一次轮询读取更多数据
- **退出条件**：poll 返回 0 字节时重置 `consecutive=0` 并 `enable_rx_intr()`
- 效果：高吞吐时减少 90%+ IRQ，空闲时 CPU 归零

**Waker 去重**（Q8.4）：`last_waker: Cell<Option<Waker>>` 跟踪上次注册的 waker，仅 `will_wake` 不同时才 `clone() + register()`，减少 ~20-40ns/poll。

### 3.3 TX Copier 循环

```
┌─────────────────────────────────────────────────────────┐
│ tx_copier_loop (task: "uart-tx-copier")                  │
│                                                          │
│  poll_fn(|cx| {                                          │
│   ① if cursor >= pending {                               │
│      pending = tx.lock().pop(&mut write_buf)             │
│      cursor = 0                                          │
│      if pending == 0 { buf.register_waker(cx); Pending } │
│    }                                                     │
│   ② uart = uart_instance().lock()                        │
│   ③ sent = uart.send_bytes(&write_buf[cursor..pending])  │
│   ④ drop(uart)                                           │
│   ⑤ cursor += sent                                       │
│   ⑥ if cursor < pending { enable_tx_intr() }             │
│   ⑦ Waker dedup: will_wake → TX_WAKER.register()        │
│   ⑧ Ready(())                                            │
│  })                                                      │
└─────────────────────────────────────────────────────────┘
```

**设计要点**：
- 使用本地 `cursor` / `pending` 状态追踪同一批次中的发送进度，避免与 `ax_println!`（内核日志）输出交错
- `send_bytes()` 批量发送：FIFO 模式下一次最多 16 字节，非 FIFO 模式下单字节
- 部分发送时 `enable_tx_intr()`，待 TX ISR 触发后继续发送剩余数据

## 4. 设备模型桥接

### 4.1 TtyRead / TtyWrite Trait 实现

```rust
// device_ops.rs
pub struct AsyncUartReader;  // 零大小类型（marker）
pub struct AsyncUartWriter;  // 零大小类型（marker, Clone）

impl TtyRead for AsyncUartReader {
    fn read(&mut self, buf: &mut [u8]) -> usize {
        DRIVER.rx.lock().pop(buf)   // 直接从 RX ring buffer 弹出
    }
}

impl TtyWrite for AsyncUartWriter {
    fn write(&self, buf: &[u8]) {
        DRIVER.tx.lock().push(buf); // 直接向 TX ring buffer 推送
    }
}
```

**设计模式**：`AsyncUartReader`/`AsyncUartWriter` 为无状态零大小类型，所有状态由 `DRIVER` 全局实例持有。这是 StarryOS TTY 框架的常规模式（对比 PTY 实现中 `PtyReader(Cons<Buffer>)` 的状态携带方式）。

### 4.2 AsyncTty 类型绑定

```rust
// ntty_async.rs
pub type AsyncTty = Tty<AsyncUartReader, AsyncUartWriter>;

lazy_static! {
    pub static ref ASYNC_TTY: Arc<AsyncTty> = Tty::new(
        Arc::default(),
        TtyConfig {
            reader: AsyncUartReader,
            writer: AsyncUartWriter,
            process_mode: ProcessMode::External(Box::new(move |waker| {
                DRIVER.rx.lock().poll.register(&waker);
            })),
        },
    );
}
```

**ProcessMode::External**（Q7 O42）：
- 创建独立 tty-reader 任务，waker 注册在 `RingBufRx.poll`（PollSet）上
- 数据到达路径：RX copier push → `RingBufRx.poll.wake()` → tty-reader 运行 → `InputReader::poll()` → ldisc 通知用户态 `read()`
- 与 `ProcessMode::Manual` 的区别：waker 保持注册直到数据就绪，消除无数据时的 yield storm

### 4.3 /dev/console 注册与用户态路径

```
entry.rs::init()
  → uart_init::init_uart_hardware()    // UART MMIO 初始化
  → register_irq_hook(isr_handler)     // IRQ 10 注册
  → DRIVER.start_rx_copier()           // 启动 RX copier 任务
  → DRIVER.start_tx_copier()           // 启动 TX copier 任务
  → ASYNC_TTY.bind_to(&proc)           // 绑定为 init 进程的控制终端
  → add_stdio(&mut fd_table)           // stdin/stdout/stderr → /dev/console
```

用户态 I/O 路径：`read(0, buf, n)` → VFS → DeviceOps::read_at → Tty::read_at → ldisc::read → `block_on(poll_io(...))` → tty-reader 任务 → `InputReader::poll()` → `AsyncUartReader::read()` → `DRIVER.rx.lock().pop(buf)`。

## 5. 端到端数据流

### 5.1 接收路径 (RX)

```
┌────────┐   IRQ   ┌───────────┐  wake   ┌───────────┐ receive_bytes() ┌──────────┐
│ NS16550 │ ──────→ │ ISR       │ ──────→ │ RX copier │ ───────────────→ │ UART FIFO │
│ 硬件    │ ←────── │ handler   │         │ (task)    │                  │ (16B)    │
└────────┘         └───────────┘         └─────┬─────┘                  └──────────┘
                                                │ push_slice()
                                                ▼
                                         ┌─────────────┐
                                         │ RingBufRx    │  64 KB, SPSC, lock-free
                                         │ (HeapRb<u8>) │
                                         └──────┬──────┘
                                                │ pop_slice()
                                                ▼
              ┌─────────────────────────────────────┐
              │ AsyncUartReader::read()              │  ← TtyRead trait
              │   → InputReader::poll()              │  ← ldisc 行规则处理
              │     → canonical/raw mode processing  │     (ICRNL, ECHO, etc.)
              │     → buf_tx.push_slice()             │
              └──────────────┬──────────────────────┘
                             │ Tty::read_at()
                             ▼
                    ┌─────────────────┐
                    │ 用户态 read()   │
                    │ /dev/console    │
                    └─────────────────┘
```

**拷贝次数**（自硬件到用户态）：
1. UART FIFO → `rx_copier_loop` 的 `read_buf`（`receive_bytes()`）
2. `read_buf` → `RingBufRx`（`push_slice()`）
3. `RingBufRx` → `InputReader::read_buf`（`AsyncUartReader::read()` → `pop_slice()`）
4. `InputReader::read_buf` → `ldisc::buf_tx`（`push_slice()`，经过行规则处理）
5. `ldisc::buf_tx` → 用户态缓冲区（`pop_slice()`）

共 5 次拷贝。已通过 Q10.2（BUF_SIZE 80→256 扩容 + `push_slice` 批量写入）优化第 4→5 步。

### 5.2 发送路径 (TX)

```
┌─────────────────┐
│ 用户态 write()  │
│ /dev/console    │
└────────┬────────┘
         │ Tty::write_at() → ldisc output → AsyncUartWriter::write()
         ▼
┌─────────────────────────────────────┐
│ RingBufTx (HeapRb<u8>, 64 KB)      │  ← push_slice()
└──────────────┬──────────────────────┘
               │ pop_slice() → poll.wake()
               ▼
┌──────────────────────────────────────────────┐
│ TX copier (task)                              │
│   send_bytes(&write_buf[cursor..pending])     │
│   → UART FIFO (max 16B per call)              │
│   → 物理串口线                                │
└──────────────────────────────────────────────┘
         ↑ IRQ (THRE)
┌────────┴──────────┐
│ ISR handler       │
│  TX_WAKER.wake()  │
│  DRAIN_WAKER.wake│  ← tcdrain 条件唤醒
└───────────────────┘
```

### 5.3 tcdrain 路径

```
用户态 ioctl(TCSBRK) / tcdrain()
  → ctl.rs: TCSBRK handler
    → block_on(poll_fn(|cx| {
        ① 等 RingBufTx 排空: tx.poll.register(cx.waker())
        ② 等 UART 发送完成: TCDRAIN_ACTIVE.store(true)
           DRAIN_WAKER.register(cx.waker())
           check LSR::TRANSMITTER_EMPTY
      }))
```

## 6. 关键设计决策汇总

| 决策 | 说明 | 阶段 |
|------|------|:---:|
| **stride = 1** | NS16550 为字节寻址，stride=4 导致 LoadFault | Q0 |
| **AtomicWaker 替代 PollSet** | UART 场景 waker 固定（3 个），O(1) 唤醒 vs O(n) BTreeMap | Q4 |
| **rx/tx 独立锁** | `Mutex<RingBufRx>` / `Mutex<RingBufTx>` 分离，消除 false contention | Q5 |
| **NAPI 中断合并** | 连续 ≥16 次成功后切轮询，batch=64；0 字节时退出 | Q5/Q8.1 |
| **IER 缓存 (AtomicU8)** | 避免 RMW 读硬件寄存器，enable/disable 仅一次 MMIO write | Q5 O27 |
| **ProcessMode::External** | 消除 yield storm，waker 仅在数据就绪时被唤醒 | Q7 O42 |
| **ISR 无锁化** | `read_isr_unlocked()` 直接 volatile read，消除 SpinNoIrq | Q8.2 |
| **IER API 规范化** | `set_ier()` 替代裸 `write_volatile`，消除规则违规 | Q8.3 |
| **DRAIN_WAKER 条件化** | `TCDRAIN_ACTIVE` 门控，无 tcdrain 等待者时跳过 wake | Q8.5 |
