> Part of StarryOS codebase analysis (branch: uart-16550-lichee)

> See also: [uart-async-qemu-d1-first-replan.md](uart-async-qemu-d1-first-replan.md), [arceos-true-board-validation.md](arceos-true-board-validation.md)

## 1. 目标

Q20 的目标是补齐 benchmark 证据，不改 UART 驱动语义。
后续 `openspec-plan` 应把它拆成可验证的小任务。

Q20 应回答四个问题：

| 问题 | 现状 | Q20 输出 |
|------|------|----------|
| latency / jitter | S10/S14 已有 `print_tx_latency_diag()`；S20/S21 仍主要用普通 summary | S10/S14/S20/S21 都输出 `p99/p50`、`max/p50`、`slow_over_line_plus10ms` |
| CPU / counter | D1 `BENCH_D1_DIAG` 只在 S11 打印 TX debug snapshot；kernel benchmark 只打印启动期 IRQ count | 每个关键 policy 输出 TX counter delta；QEMU 与 D1 格式一致 |
| RX fixed payload | S31 已有 `BENCH_RX_FIXED_BYTES` 开关，但 Makefile 默认是 0 | QEMU 和 D1 都有 PASS 样本，且记录输入方式 |
| raw evidence | Q19C 已归档历史日志；Q20 尚无独立目录 | QEMU rootfs log 和 D1 serial log 分开保存 |

边界：D1 是单 hart。Q20 数据不能证明 O63 SMP 正确性。
多 hart stress 仍属于 Q24。

## 3. 缺口拆分

### Q20.1 jitter summary

当前 `print_tx_latency_diag()` 已输出：

```text
avg_ms p50_ms p95_ms p99_ms max_ms slow_gt10ms slow_over_line_plus10ms max_line_ratio
```

缺的是统一指标。
建议新增或扩展 diag 输出：

```text
p99_p50_ratio max_p50_ratio
```

S10 和 S14 已调用 `print_tx_latency_diag()`。
S20/S21 应切到同一 diag，或者在普通 summary 后追加同格式 diag。

### Q20.2 CPU / counter summary

已有 counter 分两层。

| 层 | 已有字段 | 限制 |
|----|----------|------|
| driver telemetry | `tx_poll`、`tx_no_progress`、`tx_hw_bytes` | 目前没有用户态 ioctl 输出这些字段 |
| TX debug snapshot | `user_push_*`、`ring_pop_*`、`hw_send_*`、`slow_poll_exh`、`yield_exh` | 只在 `BENCH_D1_DIAG` 的 S11 输出 |
| ISR | `IRQ_COUNT` | kernel benchmark 启动时打印，不是 per-section delta |

Q20 不必先做 cycle 精确测量。
可先用 counter delta 作为 CPU/copy proxy：

```text
bytes_per_user_call
bytes_per_ring_pop
bytes_per_hw_send
hw_zero_per_kb
no_progress_per_kb
irq_delta
```

实现上建议把 `UART_TXDBG_RESET/SNAPSHOT` 从 D1-only 编译宏改为 QEMU+D1 都可用。
如果 QEMU 不启用 `BENCH_D1_DIAG`，会缺同格式对照。

### Q20.3 RX fixed payload

S31 已实现轮询读取。
当前默认 `BENCH_RX_FIXED_BYTES=0`，所以结果是 SKIPPED。

Q20 需要两个 gate：

| 平台 | gate |
|------|------|
| QEMU | 编译 `BENCH_RX_FIXED_BYTES=N`，启动 benchmark 后注入 N 字节，S31 PASS |
| D1 | `benchmark-fullbench-elf` 同样编译 N，真板串口发送 N 字节，S31 PASS |

固定 payload RX 不等于 RX 吞吐 benchmark。
它先证明 `/dev/console` read path 能收到确定字节数。
吞吐/延迟结论要等输入可重复后再写。

### Q20.4 raw evidence

建议新建证据目录：

```text
.claude/analysis/q20-evidence/
  qemu-rootfs.log
  d1-fullbench-command.log
  README.md
```

README 记录：

| 字段 | 内容 |
|------|------|
| build command | `make tests/benchmark` / `make lichee-fullbench-command` |
| benchmark macros | `BENCH_RX_FIXED_BYTES`、`BENCH_D1_DIAG`、target mode |
| run command | QEMU 启动命令或真板刷写/串口命令 |
| input injection | RX fixed payload 的发送方式 |
| expected sections | S00/S10/S11/S12/S13/S14/S20/S21/S30/S31 |

不要只把汇总表写进 `docs/benchmark-report-async.md`。
raw log 是 gate 证据。

## 4. 建议任务顺序

| 顺序 | 任务 | 验证 |
|------|------|------|
| 1 | 给 S20/S21 补同格式 jitter diag | 本地编译 `tests/benchmark` |
| 2 | 把 TX debug snapshot 输出扩展到 QEMU+D1 | QEMU 和 D1 都出现 `diag=txdbg` |
| 3 | 增加 counter 派生字段 | 输出 bytes/call、zero/kb、no-progress/kb |
| 4 | 增加 RX fixed payload 构建入口 | S31 不再默认 SKIPPED 的专用 target |
| 5 | 跑 QEMU rootfs | 保存 `qemu-rootfs.log` |
| 6 | 跑 D1 command-entry fullbench | 保存 `d1-fullbench-command.log` |
| 7 | 更新性能报告 | 只引用 raw evidence，不替代 raw evidence |

每步只改 benchmark 或诊断输出。
若需要改 `tx_copier_loop()` 语义，应退出 Q20，另开优化任务。

## 5. 风险

| 风险 | 处理 |
|------|------|
| S31 阻塞等待输入 | 保持 nonblocking + timeout；raw log 记录输入时刻 |
| stdout backlog 污染小包数据 | 每节继续 `fflush + tcdrain`，保留 pre-section drain |
| QEMU throughput 被误读 | QEMU 只做路径/相对行为，不声明线速 |
| D1 P99 长尾被误判为丢中断 | 同看 `slow_poll_exh`、`yield_exh`、`hw_send_zero` 和 throughput |
| counter 不是精确 CPU cycles | 文档中称为 CPU/copy proxy，不称为 CPU 占用率 |

## 6. 给后续 plan 的输入

OpenSpec change 可以用这些 acceptance criteria：

| Gate | PASS 条件 |
|------|-----------|
| jitter | S10/S14/S20/S21 输出 p50/p99/max 和 ratio |
| counter | QEMU+D1 至少 S11 输出 TX counter delta 和派生字段 |
| RX fixed | QEMU+D1 S31 均 PASS，target bytes 与 received 一致 |
| evidence | `.claude/analysis/q20-evidence/` 有 QEMU 与 D1 raw log |
| boundary | 文档明确 Q20 不声明 SMP 正确性，不改 driver 语义 |
