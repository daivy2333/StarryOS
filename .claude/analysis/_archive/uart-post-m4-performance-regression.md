## 1. 结论

用户在同一 benchmark 条件下回退 StarryOS 与 uart_16550 后确认：pre-M4 64B `write+tcdrain` 为 406µs，M4 后为 29.99ms，实际 commit 回归是 **73.9×**。此前“5.4×”是 29.99ms 相对 115200bps 理论线速 5.56ms 的比值，不是 before/after 回归倍数。

精确代码边界位于 uart_16550 `7c1e9f4`：TX FIFO 满时从继续 `Poll::Ready(())` 改为 `enable_tx_intr(); return Poll::Pending;`。M4 前 copier 在同一次调度中持续重试 `send_bytes()`，实质是 busy-poll；M4 后 copier 每发送最多 16B 就睡眠，后续进展依赖 THRE IRQ 唤醒并重新调度。axtask waker 使用 `unblock_task(task, false)`，StarryOS 为 100Hz tick，因而每个后续 FIFO refill 形成约 10ms 台阶；64B 首批后还需 3 次 refill，对应约 30ms。该机制与回退数据、提交差分和延迟数量级一致，根因已确认。

原“`RingBufTx` writer 与 ISR 竞争同一把 `SpinNoIrq`”诊断不成立。源码中存在两把独立锁：

- `RingBufTx.writer` 内的 `ArceOsRawMutex(SpinNoIrq<()>)` 只保护 TX producer；TX copier 的 reader 端不获取它。
- `ArceOsUartPort.uart: SpinNoIrq<Uart16550<_>>` 保护硬件寄存器，竞争方是 copier、ISR 和 `tcdrain`，不是 TX ring writer。

64B benchmark 每轮只调用一次 `RingBufTx::push()`。一次 task-context 锁不能解释约 29.6ms 的新增墙钟时间；删除 `RefCell` 最多优化固定小开销，不应作为首要修复。`62755f0` 增加的 ring/copier 原子 metrics 会增加热路径成本，但它发生在 backpressure 行为变更之后，也不具备 10ms 量级机制，因此列为 P2。

此外，M4 后的完成状态机仍有三个独立正确性缺陷：

1. THRE 表示 FIFO/THR 空，不保证 shift register 已空；关闭 THRE 后未必再有 TEMT IRQ，纯 `drain_waker` 等待可能永久挂起。
2. `accepted == popped` 或 `TX_RING.is_empty()` 只说明数据已被 copier 搬入本地 `write_buf`，不说明它已提交到 UART；`tcdrain` 可在 pop 与 MMIO write 之间提前返回。
3. `TtyWrite::write()` 忽略 `tx.push()` 的短写结果，而 TTY `write_at()` 始终返回 `buf.len()`，ring 满时会静默丢数据。

因此应先验证调度节拍并修正 TX 完成模型，再考虑 `RefCell`、内联和 ISR 单锁等微优化。

## 2. 当前端到端路径

```text
userspace write(64B)
  → Tty::write_at
  → AsyncUartWriter::write (TtyWrite)
  → RingBufTx::push                  [writer SpinNoIrq，一次/系统调用]
  → PollSet::wake
  → TX copier::pop_batch             [reader 无锁，最多取 64B staging]
  → ArceOsUartPort::send_bytes       [UART SpinNoIrq]
  → Uart16550::send_bytes            [每次最多填 16B FIFO]
  → THRE IRQ
  → AsyncUartDriver::handle_irq
      → read_isr                     [UART lock #1]
      → update_ier                   [UART lock #2]
      → tx_waker.wake
      → is_transmitter_empty         [UART lock #3]
  → axtask AxWaker::wake_by_ref
      → unblock_task(task, false)     [入 ready queue，不立即 resched]
  → TX copier 下一次获得 CPU
  → 再填 16B FIFO
```

64B 在 FIFO 已启用时通常需要 4 次 `send_bytes()`，即 3 次 IRQ 驱动的后续 refill。锁数量增加是真实变化，但墙钟时间主要由“wakeup 到 task 实际运行”的间隔决定。

## 3. M4 后改动的成本归因

| 改动 | 实际频率（64B/轮） | 归因判断 | 优先级 |
|---|---:|---|---:|
| TX writer `UnsafeCell → Mutex<SpinNoIrq, RefCell<_>>` | 1 次 | 固定开销；`wake()` 仍在关中断临界区内，范围过大，但不足以解释 24ms | P2 |
| per-port ISR backend 方法 | 每次 THRE IRQ 约 3 次 UART lock | 可增加 IRQ 延迟；锁彼此短且无 producer writer 竞争，不能解释 10ms 量级 | P2 |
| M4 TX backpressure `Ready→Pending` (`7c1e9f4`) | 每个 16B FIFO 批次 | **确认主因**：把进展从同步重试改为 IRQ 唤醒后重新调度，产生约 10ms/refill | P0 |
| M4 ring/copier metrics (`7c1e9f4`, `62755f0`) | 每次 push/pop/poll/send | 原子操作是次要热路径成本，不产生 10ms 台阶 | P2 |
| TX copier register→recheck（M4 后正确性审计） | 仅 ring 空路径多一次 `pop_batch` | 正确性所需，成本很小 | P3 |
| async write 满 ring 时 double-push | 仅 backpressure | 64B/64KiB ring benchmark 不触发 | 排除 |
| real `tcdrain` / TEMT | 每轮进入完成状态机 | 改变 benchmark 语义并暴露调度/完成模型；属于主要调查范围 | P0 |
| per-port `AtomicWaker` | 每个 THRE IRQ | waker 本身不是问题；axtask 消费 waker 时 `resched=false` 才是关键 | P0 |

### 3.1 writer 锁的真实问题

`RingBufTx::push()` 在 `writer.lock()` 内执行：数据复制、4 组原子指标更新以及 `poll.wake()`。`ArceOsRawMutex` 会关闭本 CPU 中断，因此 `PollSet::wake()` 也处于关中断区。

这不是 5.4× 的充分根因，但设计不合理：保护 `Writer` 所需的临界区应只包含 `borrow_mut().push(...)`。指标计算和任务唤醒应在解锁、恢复中断后执行。若 Async writer 从不在 ISR 使用，RawMutex 也应使用 task-context 的 `SpinNoPreempt` 或等价 MPSC 原语，而不是 `SpinNoIrq`。

### 3.2 ISR 锁的真实问题

`handle_irq()` 的 THRE 分支通过三个独立 `UartPort` 方法获取同一个 UART 锁。它们会和 copier 的 `send_bytes()`、`tcdrain` 的 TEMT 查询竞争。可合并为一次 IRQ transaction，但预期收益是微秒以内和更强的一致性，不是几十毫秒。

更重要的是 StarryOS 仍保留 `CACHED_IER + enable_tx_intr()` callback，而 `handle_irq().update_ier()` 只更新硬件、不更新 cache。cache 与硬件状态已分裂，后续 callback 会基于陈旧值重写 IER。这违背正确性修复设计中“移除外置 cache/enable callback”的目标。

## 4. 已确认根因：M4 backpressure 将 FIFO refill 绑定到粗粒度调度

本地 axtask `AxWaker::wake_by_ref()` 的关键行为是：

```text
rq.unblock_task(task, false)
```

`false` 明确表示只把 blocked task 放回 run queue，不设置 preempt/resched。StarryOS `ticks-per-sec = 100`，时间片粒度为 10ms。

M4 前后状态转换如下：

```text
pre-M4: send_bytes=0 → Poll::Ready → 外层 loop 立即再 poll → busy-poll 直到可写
M4:     send_bytes=0 → register + enable THRE → Poll::Pending
                              ↓
                     IRQ wake → ready queue → 后续调度才 refill
```

因此每次 THRE IRQ 后 copier 不能立即运行时：

```text
T(64B) ≈ 首批发送 + 3 × 调度等待 + 线速时间
       ≈ 3 × 10ms + 小量 MMIO/系统调用开销
```

这与 406µs→29.99ms 的回退实测和提交差分一致。该模型还预测：

- 1–16B 不出现 refill 台阶；
- 17–32B 增加约 10ms；
- 33–48B 再增加约 10ms；
- 49–64B 再增加约 10ms；
- 将 tick 从 100Hz 改为 1000Hz 后，台阶应从约 10ms 缩小到约 1ms；
- 仅恢复该 hunk 的同步重试时性能恢复，但 CPU busy-poll 回归；
- bounded fast-path retry 命中时台阶消失，超过预算后仍安全回落到 IRQ Pending。

根因确认不等于直接恢复旧 busy-poll。修复必须同时满足低延迟与空闲 CPU 不自旋：先用 selective-hunk A/B 见证，再实现有上限的 fast-path retry；若真实瓶颈位于 IRQ-arrival→copier-run，则进一步评估 runtime 可用的 resched-aware 接口。提高全局 tick 或 ISR 搬运数据违反当前性能/架构约束，不作为首选方案。

## 5. TX 完成状态机缺陷

### 5.1 `drain_waker` 没有可靠事件源

16550 的 THRE 在 FIFO/THR 为空时成立，TEMT 还要求 shift register 为空。最后一个 THRE IRQ 到达时，TEMT 可能仍为 0；handler 随即关闭 THRE。硬件通常不会仅因 TEMT 从 0 变 1 再产生一种新 IRQ，因此等待 `drain_waker` 的 future 可能永远不再被 poll。

正确实现需要以下之一：

- 用定时器/有界协作轮询 TEMT；
- 在最后一批提交后按剩余字符时间设置 deadline；
- 保持明确的硬件支持事件（若目标 UART 确实提供 TX-complete IRQ）；
- 在 ISR 直接 refill 并由最后一次 completion 检查结合 timer 收尾。

### 5.2 ring empty 不是 hardware committed

`tx_copier_loop()` 先 `pop_batch()` 到 64B 本地 staging，再分多次写 16B FIFO。此时 ring 已空且 `popped == accepted`，但最多仍有 64B 未进入硬件。`tcdrain` 在该窗口看到 ring empty + 旧 TEMT=true 时可提前成功。

需要显式状态，例如：

```text
queued_in_ring + staged_in_copier + bytes_in_hw
```

至少应有 `tx_inflight`/generation counter，使 drain 条件成为：ring empty、staging empty、最后提交 generation 已完成、TEMT=true。

### 5.3 TTY 短写被伪装成成功

同步 `TtyWrite` 接口返回 `()`，`AsyncUartWriter::write()` 丢弃 `push()` 返回值；上层 `write_at()` 无条件返回输入长度。只要 TX ring 满，用户态认为写成功但数据已进入 `dropped` 计数。性能 benchmark 也会把未发送字节计入 total。

应让 TTY writer 支持短写/`WouldBlock`，或在同步入口阻塞直至全部入 ring。仅靠诊断 counter 不能满足 write 契约。

## 7. 修复方向与顺序

1. **P0：固化根因见证。** 把 E0/E0.1、16/17/32/33B 台阶和 CPU idle/busy 指标写入自动 benchmark，禁止只保留文档结论。
2. **P0：消除 refill 调度量化。** 在 copier 内实现有严格次数/时间预算的 fast-path retry；预算耗尽后仍执行 register→enable→Pending，既避免旧版无限 busy-poll，也避免 QEMU 快速可写场景无条件睡到下个调度点。
3. **P0：重构 completion state。** 显式表示 ring/staging/hardware 三阶段，给 tcdrain 一个无竞态谓词；TEMT 收尾使用可靠 timer 或硬件事件。
4. **P1：统一 IER 所有权。** 删除 `CACHED_IER + enable_*_intr` 分裂路径，让 driver/UartPort 持有唯一 IER shadow，并在一次 UART lock transaction 中更新。
5. **P1：修复 write 契约。** 不允许 `TtyWrite` 静默丢弃短写。
6. **P2：缩小 producer 临界区。** `push` 只在锁内操作 Writer；metrics/wake 移到锁外；确认无 ISR producer 后用 task-context mutex。
7. **P2：诊断 metrics 降成本。** 评估 feature gate、采样或批量累计，避免每个 push/pop/poll 都做多次全局原子操作。
8. **P2：合并 ISR 寄存器事务。** 在不违反 ISR 极简原则的前提下减少重复寄存器锁，并保证 IER 快照一致。

不建议把“回退到无锁 `UnsafeCell<Writer>`”作为生产修复：`AsyncUartWriter: Clone` 允许多 producer，直接回退会重新引入已确认的可变别名 UB。若项目实际只需要单 producer，应通过类型能力取消 Clone/限制构造，而不是依赖注释。
