/// Sets the Interrupt Enable Register directly.
///
/// This bypasses the builder pattern for cases where IER needs to be
/// modified at runtime (e.g., disabling/enabling specific interrupts
/// during NAPI polling or ISR handling).
pub fn set_ier(&mut self, ier: IER) {
    // SAFETY: We operate on valid register addresses.
    unsafe {
        self.backend.write(offsets::IER as u8, ier.bits());
    }
}

## 2. `set_ier()` 的必要性分析

### 2.1 使用场景

StarryOS 异步 UART 驱动需要**运行时动态启用/禁用特定中断**：

```
enable_rx_intr()  → write_ier(CACHED_IER | IER::DATA_READY)
disable_rx_intr() → write_ier(CACHED_IER & !IER::DATA_READY)
enable_tx_intr()  → write_ier(CACHED_IER | IER::THR_EMPTY)
disable_tx_intr() → write_ier(CACHED_IER & !IER::THR_EMPTY)
```

调用模式：ISR 禁用中断 → copier 处理完毕 → 重新启用中断。每次 Shell 交互产生数十次 IER 切换。

### 2.2 为什么不能绕过

| 方案 | 可行性 | 问题 |
|------|:---:|------|
| `uart.init(Config { interrupts: ... })` | ❌ | 重新初始化全部配置（波特率/LCR/FCR/MCR），破坏运行时状态，且 drain TX 阻塞 |
| 裸 `write_volatile` | ❌ | **违反项目规则**：MMIO 必须走 uart_16550 API（CLAUDE.md §六 ISR 极简原则） |
| 访问 `backend` 字段 | ❌ | `backend` 是私有字段，`Backend` trait 已 sealed |
| 上游添加 `set_ier()` | ✅ | 12 行，对称于已有的 `ier()` getter |

### 2.3 Q8.3 的历史背景

`set_ier()` 是 Q8.3 专门添加的。在此之前，`write_ier()` 直接使用裸 `write_volatile`：

```rust
// Q8.3 之前的违规代码
unsafe {
    uart_ptr.add(offsets::IER).write_volatile(value);
}
```

Q8.3 明确将此标记为规则违规并修复。如果删掉 `set_ier()` 回到裸写，等于主动引入已知规则违规。

### 3.3 `set_ier()` 上游化可行性

**极高可行**。理由：

1. `set_ier()` 是 `ier()` getter 的对称 setter，API 完整性考量（getter 存在 → setter 也应存在）
2. 上游内部已经在 `init()` 中写入 IER（line 498），`set_ier()` 只是将这段逻辑暴露为公共 API
3. 代码量极小（12 行 + SAFETY 注释 + 文档注释）
4. 有明确的使用场景（内核驱动运行时中断控制）
5. 维护者 @phip1611 对代码质量和 API 完整性有高要求，这种对称 API 补全通常受欢迎

**建议的 PR 说明**：
> Add `set_ier()` as the symmetric setter to the existing `ier()` getter. This is needed for kernel drivers that dynamically enable/disable individual interrupts at runtime (e.g., NAPI-style polling in interrupt-driven UART drivers).

## 5. 建议

### 推荐：方案 A → 方案 B（两阶段）

**第一阶段（当前）**：保留本地 fork。维护成本可忽略（12 行代码，上游 v0.6.0 无新发布）。

**第二阶段（可选，低优先级）**：向上游提交 `set_ier()` PR，merge 后修改 `kernel/Cargo.toml`：

```toml
# 修改前
uart_16550 = { path = "../../uart_16550" }

# 修改后
uart_16550 = "0.7"  # 或包含 set_ier() 的版本
```

### 不推荐方案 C

`set_ier()` 是一个纯软件接口问题 — 它只是将已有的 `backend.write(offsets::IER, ...)` 封装为公共 API。QEMU 上的验证同等有效，真板不会暴露任何相关问题。

### 风险提示

如果上游不合并 `set_ier()`（概率极低），我们可以考虑：
- 继续使用本地 fork（成本可忽略）
- 或通过 `init(Config { interrupts: ..., ..current_config.clone() })` 变通（但会引入不必要的 baud rate 重设等副作用）
