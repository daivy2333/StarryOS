## 2. 新发现：现有计划之外的优化机会

### 2.1 正确性 / 规则违规（🔴 必须修复）

#### 🔴 #1 NAPI 模式永远不会退出（`async_driver.rs:51`）

**症状**：一旦连续成功读取超过 `NAPI_THRESHOLD=16` 次，`consecutive` 计数器进入单调递增模式（`consecutive += 1`），**永远不会回退到中断模式**。数据停止时 RX 中断永久禁用，CPU 原地空转轮询空 FIFO。

**修复**：零字节读取或超时时重置 `consecutive = 0` 并调用 `enable_rx_intr()`。

**影响**：功能正确性 — QEMU 上可能不明显（虚拟 UART 永不空闲），真板上会导致持续 CPU 占用。

#### 🔴 #2 ISR 获取 SpinNoIrq 锁（`isr.rs:10`）

**症状**：中断处理程序第 10 行 `uart_instance().lock()` 获取 `SpinNoIrq` 锁。违反 ISR 极简原则："ISR MUST 只做：(1) 读 ISR，(2) 禁中断，(3) wake，(4) 返回。禁止锁操作。"

**修复**：将 `isr()` / `disable_*_intr()` 调用移到锁外部，或实现无锁的 MMIO 读取路径。

**影响**：规则违规 + 每次中断额外 spinlock 开销（~100-200ns）。

#### 🔴 #3 IER 直接 write_volatile 绕过 uart_16550 API（`uart_init.rs:72`）

**症状**：`write_ier()` 使用 `unsafe { core::ptr::write_volatile(ptr.add(offsets::IER), value) }` 裸写 MMIO。违反项目规则："所有 MMIO 操作 MUST 封装在 uart_16550 安全 API 之后，禁止 write_volatile 裸地址。"

**修复**：向 `uart_16550` crate 添加 `fn set_ier(&mut self, value: IER)` 公共方法，或使用已有的 `ier_mut()` 模式。

**影响**：安全违规 + CACHED_IER 可能与硬件不同步（无读回验证）。

### 2.2 性能优化（🟡）

#### 🟡 #4 读路径 5 次数据拷贝

| 拷贝 | 从 | 到 | 大小 | 位置 |
|------|----|----|------|------|
| C1 | UART FIFO | copier read_buf | batch(64/1024) | `async_driver.rs:48` |
| C2 | copier read_buf | driver RingBufRx (64KB) | batch | `async_driver.rs:50` |
| C3 | driver RingBufRx | InputReader read_buf (80B) | 0~80B | `ldisc.rs:83` |
| C4 | InputReader read_buf | ldisc StaticRb (80B) | processed | `ldisc.rs:90` |
| C5 | ldisc StaticRb | user buf | total | `ldisc.rs:364` |

C3→C4 在同一个 `InputReader::poll()` 中立即完成，可合并为一次拷贝。

#### 🟡 #5 ldisc 锁在 async wait 期间持有（`tty/mod.rs:88`）

`Tty::read_at()` 中 `self.ldisc.lock()` 跨越整个 `block_on(poll_io(...))` 调用，阻塞并发 poll/select 的 `register_rx_waker()`。

#### 🟡 #6 copier waker clone 开销（`async_driver.rs:53-55,82-84`）

每个 `poll_fn` 迭代执行 2 次 `Waker::clone()` + `will_wake()` + `AtomicWaker::register()`。对于单线程 copier，waker 几乎不变，可简化为一次 `will_wake` 检查。

#### 🟡 #7 ready_to_send() 中冗余 MSR/MCR 读取

`uart_16550::send_bytes()` 每次批次执行 `ready_to_send()` → 读取 LSR + MSR + MCR。无硬件流控时 MSR/MCR 读取是冗余的（每次批次 ~200ns × 2）。

### 2.3 架构改进（🟡）

#### 🟡 #8 ldisc 缓冲区仅 80 字节

`ringbuf::StaticRb<u8, 80>` 限制了突发吸收能力。在高波特率（≥921600）下，这个大小可能成为瓶颈。

#### 🟡 #9 DRAIN_WAKER 每次 TX ISR 触发

`DRAIN_WAKER.wake()` 在每个 TX ISR 上无条件执行，即使没有 tcdrain 等待者。`AtomicWaker::wake()` 是 SeqCst 原子操作。

#### 🟡 #10 clone.rs fork 路径 9 次 clone

每次 `fork()` 触发 ~9 次 `Arc::clone()` / `Vec::clone()`，其中大部分在后续 `execve()` 被立即替换。
