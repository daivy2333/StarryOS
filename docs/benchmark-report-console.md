## 2. 内核态测试结果

### 2.1 polling TX 速度

**测试方法**：调用 `ax_println!` 输出 10 行 "[BENCH] test"，测量总耗时

**测试代码**：
```rust
let iterations = 10;
let start_time = monotonic_time_nanos();

for _ in 0..iterations {
    ax_println!("[BENCH] test");
}

let end_time = monotonic_time_nanos();
let elapsed_ns = end_time - start_time;
let throughput_kbps = total_bytes as f64 / elapsed_s / 1024.0;
```

**测试结果**：

| 指标 | 值 | 说明 |
|------|-----|------|
| **polling TX 速度** | 483.25 KB/s | ax_println! 输出速度 |
| **测试数据量** | 120 字节 | 10 行 × 12 字节 |
| **测试耗时** | 0.24 毫秒 | 纳秒级精度 |
| **硬件线速** | 11.52 KB/s | 115200 bps 理论极限 |

**分析**：
- polling TX 速度（483 KB/s）远超硬件线速（11.52 KB/s）
- 测量的是 CPU 输出到 FIFO 的速度
- 不包括数据在串口线上的传输时间
- ax_println! 使用轮询方式，不经过异步路径

### 2.2 内存占用

**测试结果**：

| 组件 | 大小 | 说明 |
|------|------|------|
| **RX Buffer** | 0 KB | 无缓冲区 |
| **TX Buffer** | 0 KB | 无缓冲区 |
| **驱动结构体** | 0 KB | 无额外结构 |
| **总计** | 0 KB | 直接硬件访问 |

**分析**：
- Console 使用 `axhal::console::write_bytes` 直接访问硬件
- 无 Ring Buffer，无额外内存分配
- 每个字节都获取锁并直接写入 FIFO

### 2.3 Shell 功能测试

**测试结果**：

| 测试项 | 结果 | 说明 |
|--------|------|------|
| **echo 命令** | ✅ 正常 | 输出正确 |
| **ls 命令** | ✅ 正常 | 列出文件 |
| **cd 命令** | ✅ 正常 | 切换目录 |

**分析**：
- Shell 基本功能正常
- 阻塞式 I/O 不影响功能
- 响应时间可接受

## 3. 用户态测试结果

### 3.1 TX 吞吐量测试

**测试方法**：
```c
// 10 次写入，每次 1024 字节
const int test_size = 1024;
const int iterations = 10;

for (int i = 0; i < iterations; i++) {
    write(fd, buf, test_size);
}
```

**测试结果**：

| 指标 | 值 | 说明 |
|------|-----|------|
| **write() 速度** | 572.05 KB/s | 用户态写入速度 |
| **测试数据量** | 10,240 字节 | 10 × 1024 |
| **测试耗时** | 0.017 秒 | 17 毫秒 |
| **线速百分比** | 4965.7% | 远超理论极限 |

**分析**：
- write() 速度（572 KB/s）远超硬件线速（11.52 KB/s）
- 测量的是 write() 系统调用的速度
- 不包括串口传输时间
- QEMU 的串口模拟不等待数据发送

### 3.2 write() 延迟测试

**测试方法**：
```c
// 100 次单字节写入
for (int i = 0; i < 100; i++) {
    clock_gettime(CLOCK_MONOTONIC, &start);
    write(fd, &tx, 1);
    clock_gettime(CLOCK_MONOTONIC, &end);
    latencies[i] = end - start;
}
```

**测试结果**：

| 指标 | 值 | 说明 |
|------|-----|------|
| **P50 延迟** | 16.3 µs | 中位数延迟 |
| **P95 延迟** | 29.5 µs | 95 分位延迟 |
| **P99 延迟** | 278.4 µs | 99 分位延迟 |
| **最小延迟** | 8.4 µs | 最快一次 |
| **最大延迟** | 278.4 µs | 最慢一次 |
| **平均延迟** | 20.5 µs | 平均值 |

**分析**：
- P50 延迟（16.3 µs）是 write() 系统调用的延迟
- 不包括串口传输时间
- P99 延迟（278.4 µs）可能是 QEMU 调度导致
- 数据看起来合理

### 3.3 数据完整性测试

**测试方法**：
```c
// 发送 256 字节数据
char tx_buf[256];
for (int i = 0; i < 256; i++) {
    tx_buf[i] = (char)(i & 0xFF);
}
write(fd, tx_buf, 256);
```

**测试结果**：

| 指标 | 值 | 说明 |
|------|-----|------|
| **发送数据** | 256 字节 | 测试数据 |
| **接收数据** | 256 字节 | 回显数据 |
| **错误数** | 0 | 数据一致 |

**分析**：
- 数据传输正确
- 无丢失或损坏
- 阻塞式 I/O 保证数据完整性

## 4. 测试方法说明

### 4.1 内核态测试

**测量内容**：
- polling TX 速度：CPU → FIFO
- 不包括：线上传输时间

**优点**：
- 精度高（纳秒级）
- 无系统调用开销

**缺点**：
- 不测量完整路径
- 不包括用户态开销

### 4.2 用户态测试

**测量内容**：
- write() 速度：用户态 → FIFO
- write() 延迟：系统调用时间

**优点**：
- 测量完整路径
- 接近实际使用场景

**缺点**：
- QEMU 串口模拟不等待发送
- 无法测量真实线速

### 4.3 测量局限性

**无法测量的指标**：
- 串口线速（QEMU 不等待）
- 端到端延迟（需要硬件支持）
- CPU 占用（需要性能计数器）

**可以测量的指标**：
- write() 系统调用速度
- write() 系统调用延迟
- 内存占用
- Shell 功能
