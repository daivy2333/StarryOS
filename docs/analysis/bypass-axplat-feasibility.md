## 1. 核心问题

**目标**：完全绕过 axplat（外部 crate，不可修改），从硬件层到用户态接口，全栈从零实现异步串口。

**背景**：feat/uart-async-dev2 分支在尝试实现 AsyncUart 时遇到了两个关键阻塞：
- 内核上下文访问 UART MMIO 寄存器 → StoreFault/LoadFault
- ISR 上下文访问 UART MMIO 寄存器 → LoadFault（`stval=0xffffffc010000008`）

## 2. axplat 依赖全景图

### 2.1 axplat 架构

axplat 是 ArceOS 的**平台抽象层**，采用 `crate_interface` 模式定义接口，由平台专属 crate 实现：

```
axplat (base crate, v0.3.1-pre.6, crates.io)
├── ConsoleIf trait    → axplat-riscv64-qemu-virt 实现
├── InitIf trait        → axplat-riscv64-qemu-virt 实现
├── IrqIf trait         → axplat-riscv64-qemu-virt 实现
├── MemIf trait         → axplat-riscv64-qemu-virt 实现
└── PowerIf/TimeIf      → axplat-riscv64-qemu-virt 实现

axhal (v0.3.0-preview.2, crates.io)
├── 重导出 axplat::console::{read_bytes, write_bytes, irq_num}
├── 重导出 axplat::irq::{handle, register, set_enable, unregister}
├── 新增 register_irq_hook() 单槽 hook 机制
├── 重导出 axplat::mem::{phys_to_virt, virt_to_phys, ...}
└── init_early() → axplat::init::init_early()
```

### 2.2 启动全链路（UART 相关）

```
_start (boot.rs)
  → 建立启动页表（1G 块，读写执行全权限）
  → 使能 MMU
  → axplat::call_main()
    → axruntime::rust_main()
      ├─ axhal::init_early()                      ← LINE A
      │   └─ axplat::init::init_early()
      │       ├─ console::init_early()             ← UART 初始化 + MMIO 映射
      │       │   └─ MmioSerialPort::new(UART_PADDR + PHYS_VIRT_OFFSET)
      │       │   └─ uart.init(config)             ← 115200 bps, RX 中断
      │       └─ time::init_early()
      ├─ axlog::init()                             ← 开始用 axplat console 写日志
      ├─ init_allocator()
      ├─ axmm::init_memory_management()            ← LINE B: 切换最终页表
      │                                              ⚠️ UART MMIO 权限丢失
      ├─ axhal::init_later()                       ← LINE C
      │   └─ irq::init_percpu()                    ← PLIC 初始化
      ├─ axtask::init_scheduler()
      ├─ init_interrupt()                          ← 注册 timer IRQ
      ├─ enable_irqs()                             ← 全局中断使能
      └─ main()                                    ← LINE D: 用户内核入口
          └─ starry_kernel::entry::init()
              ├─ uart_init::init_uart_hardware()    ← 尝试访问 UART → LoadFault ❌
              ├─ register_irq_hook(isr_handler)     ← ISR 注册成功
              └─ N_TTY.bind_to()                   ← Console 绑定
```

**关键发现**：axplat console 在 LINE A 初始化后就能正常工作（async-uart-implementation-history.md 第 5 章），是因为它的 `MmioSerialPort` 实例在 LINE B（页表切换）**之前**创建并持有指向正确地址的裸指针。LINE B 之后，最终页表不再保留该地址范围的 RW 权限，导致内核和 ISR 中任何**新**的 UART MMIO 访问都失败。

### 2.3 axplat 的 5 个接口 trait 依赖关系

| Trait | 功能 | StarryOS 依赖方式 | 可绕过？ |
|-------|------|------------------|---------|
| **ConsoleIf** | UART 读写、irq_num | `axhal::console::read_bytes/write_bytes` (N_TTY/Console) | ✅ **可** |
| **IrqIf** | PLIC claim/complete, HandlerTable<1024>, IRQ 注册/使能 | `axhal::irq::handle/register` + `register_irq_hook` | ❌ **不可** |
| **InitIf** | init_early/later 启动生命周期 | `axhal::init_early/later` → axruntime 调用 | ❌ **不可** |
| **MemIf** | phys_to_virt, mmio_ranges, kernel_aspace | `axhal::mem::phys_to_virt` (uart_init.rs, mm/aspace) | ❌ **不建议** |
| **PowerIf/TimeIf** | 关机/重启、时钟源 | axhal 重导出 | ❌ **不建议** |

**结论：必须保留 axplat 的 {irq, init, mem, time}，只替换 {console}。不完全绕过，而是外科手术式替换。**

## 3. 一号阻塞：MMIO 页表权限问题

### 3.1 现象

```
init_uart_hardware() 中:
  phys_to_virt(0x10000000) = 0xffffffc010000000  ← 地址正确
  Uart16550::new_mmio(0xffffffc010000000)        ← 创建实例成功
  uart.isr() 读 ISR 寄存器                        ← LoadFault @ 0xffffffc010000008 ❌
  uart.init() 写 UART 寄存器                      ← StoreFault @ 0xffffffc01000001c ❌

ISR handler 中:
  uart.isr() 读 ISR 寄存器                        ← LoadFault @ 0xffffffc010000008 ❌
```

### 3.2 根因

- 启动页表（boot.rs）：1G 块映射 `0xffffffc000000000→0x00000000`，全 RWX 权限
- 最终页表（axmm::init_memory_management）：重建页表，UART MMIO 区域**未重新映射**或**映射为只读**
- RISC-V 架构：内核态和 ISR 共用同一页表（satp），无 x86 式 ring0 特权绕过
- axplat console 仍能工作：因为它在最终页表切换**之前**持有并初始化了 `MmioSerialPort`

### 3.3 可行方案

**方案 A（推荐）：在最终页表中重新映射 UART MMIO**

使用 `axhal::paging::PageTable` API 添加映射。kernel/src/mm/aspace/ 中已经有大量使用：
- `AddrSpace::map_linear()` — 创建 `virt = phys + offset` 的静态映射
- `MappingFlags::READ | MappingFlags::WRITE` 可表达读写权限
- 关键难点：`AddrSpace` 用于**用户地址空间**（有 `MappingFlags::USER`），需要找到操作**内核页表**的入口

需要验证：`axhal::paging::PageTable` 是否支持从当前活跃页表（satp CSR）创建实例并修改。

**方案 B：在 init_early 中初始化 UART**

在 axruntime 的 `rust_main()` 中，`axmm::init_memory_management()` **之前**初始化本地 UART。
- 缺点：需要修改 axruntime（外部 crate），或通过其他 hook 机制
- 优点：保证 UART MMIO 在最终页表切换前即可访问

**方案 C：phys_to_virt + write_volatile 强写（已证无效）**

`phys_to_virt()` 返回地址是正确的，问题是页表权限而非地址映射。此方案无效。

### 3.4 页表修复的验证路径

```rust
// Spiike 验证：在 entry.rs::init() 中尝试映射一页 UART MMIO
use axhal::paging::{MappingFlags, PageTable};
use memory_addr::{PhysAddr, VirtAddr, PAGE_SIZE_4K};

let vaddr = VirtAddr::from(phys_to_virt(PhysAddr::from(0x10000000)).as_usize());
let paddr = PhysAddr::from(0x10000000);
let flags = MappingFlags::READ | MappingFlags::WRITE;

// 关键：这里需要获取内核页表实例，而非用户 AddrSpace
// 如果 PageTable 支持从当前 satp 创建实例，则可以：
// let mut kpt = PageTable::from_current();
// kpt.cursor().map(vaddr, paddr, PAGE_SIZE_4K, flags)?;
```

## 5. 推荐架构

```
QEMU RISC-V (NS16550 UART @ 0x10000000)
  │
  ├─ UART MMIO (0xffffffc010000000) ── 通过修复的页表映射 → 物理 0x10000000
  │
  ├─ IRQ 10 → PLIC → axplat::irq::handle() (保留) ── 不可绕过
  │              └─ HandlerTable dispatch
  │                  └─ axhal::irq::irq_handler()
  │                      └─ register_irq_hook(uart_isr_handler)
  │                          ├─ 读 ISR 寄存器 (本地 uart_16550)
  │                          ├─ DATA_READY → rx_waker.wake()
  │                          └─ THR_EMPTY → tx_waker.wake()
  │
  ├─ RX copier task (AsyncUart 后台)
  │   └─ poll_fn loop:
  │       ├─ UART.try_receive_byte()
  │       ├─ 行规则处理 (ldisc, termios, job_control)
  │       ├─ push to ldisc rx_buf
  │       ├─ rx_waker.register()
  │       └─ Poll::Pending
  │
  ├─ TX copier task (AsyncUart 后台)
  │   └─ poll_fn loop:
  │       ├─ tx_buf.pop()
  │       ├─ UART.send_bytes()
  │       ├─ tx_waker.register()
  │       └─ Poll::Pending
  │
  └─ N_TTY (Tty<AsyncUart, AsyncUart>)
      ├─ DeviceOps trait (read_at/write_at/ioctl)
      ├─ as_pollable() → select/poll/epoll 支持
      └─ /dev/async_uart 设备节点
          │
          └─ VFS → sys_read/sys_write → fd 0,1,2
              └─ /bin/sh (init 进程，透明使用)
```

## 6. 风险矩阵

| 风险 | 严重性 | 概率 | 缓解措施 |
|------|--------|------|---------|
| MMIO 页表权限无法在内核态修复 | 🔴 致命 | 中 | Spike 验证优先；若失败则转向方案 B（boot 阶段初始化）或方案 C（Polling TX 妥协方案） |

1. **Spike 验证（阻塞解除）**：在 `entry.rs::init()` 中，尝试通过 `axhal::paging` API 修复 UART MMIO 页表权限。不解决此问题，后续一切无从谈起。

## 总结

**"完全绕过 axplat"不是一个精确的目标，精确的目标是"替换 axplat 的 ConsoleIf 实现"。**

- axplat 的 irq/init/mem/time 四个层无法也没有必要绕过（PLIC 中断控制器、启动生命周期、地址转换、时钟源是系统基础）
- ConsoleIf（UART 读写 + irq_num）完全可以替换为基于本地 uart_16550 v0.6.0 的实现
- 核心阻塞点是 MMIO 页表权限，不是 axplat 本身
- VFS/系统调用层完全透传，无需修改
- 代码量 ~320 行，时间 2 天到 2 周（取决于页表修复难度）
- 整体方案完全可行
