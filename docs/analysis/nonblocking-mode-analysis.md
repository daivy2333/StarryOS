## 2. FIONBIO 实现现状

### 2.1 系统调用层 — sys_ioctl

**文件**: `kernel/src/syscall/fs/ctl.rs:28-38`

```rust
pub fn sys_ioctl(fd: i32, cmd: u32, arg: usize) -> AxResult<isize> {
    let f = get_file_like(fd)?;
    if cmd == FIONBIO {
        let val = (arg as *const u8).vm_read()?;
        if val != 0 && val != 1 {
            return Err(AxError::InvalidInput);
        }
        f.set_nonblocking(val != 0)?;
        return Ok(0);
    }
    f.ioctl(cmd, arg)
}
```

**当前状态**: ✅ FIONBIO 已实现。从用户态读取 `arg`（0 或 1），调用 `set_nonblocking()`。

## 3. FileLike trait 的非阻塞支持

### 3.1 默认实现

**文件**: `kernel/src/file/mod.rs:156-162`

```rust
fn nonblocking(&self) -> bool {
    false
}

fn set_nonblocking(&self, _nonblocking: bool) -> AxResult {
    Ok(())
}
```

默认实现：`nonblocking()` 返回 `false`，`set_nonblocking()` 无操作。

### 3.2 File 实现

**文件**: `kernel/src/file/fs.rs:102-165`

```rust
pub struct File {
    inner: axfs::File,
    nonblock: AtomicBool,      // ← 存储非阻塞标志
}

fn set_nonblocking(&self, flag: bool) -> AxResult {
    self.nonblock.store(flag, Ordering::Release);
    Ok(())
}

fn nonblocking(&self) -> bool {
    self.nonblock.load(Ordering::Acquire)
}
```

**支持设备**: `File` 结构体（VFS 文件包装器）存储 `nonblock: AtomicBool`。

### 3.3 read() 中的非阻塞路径

**文件**: `kernel/src/file/fs.rs:128-136`

```rust
fn read(&self, dst: &mut IoDst) -> AxResult<usize> {
    let inner = self.inner();
    if likely(self.is_blocking()) {
        inner.read(dst)              // BLOCKING flag 设备走同步路径
    } else {
        block_on(poll_io(self, IoEvents::IN, self.nonblocking(), || {
            inner.read(&mut *dst)    // 非 BLOCKING 设备走 async 路径
        }))
    }
}
```

**`is_blocking()`** 检查 `NodeFlags::BLOCKING`:
```rust
fn is_blocking(&self) -> bool {
    self.inner.location().flags().contains(NodeFlags::BLOCKING)
}
```

TTY 设备返回的 flags：`NON_CACHEABLE | STREAM`（**不含 BLOCKING**）

所以 TTY 总是走 `block_on(poll_io(...))` 路径。

## 4. 关键问题：非阻塞标志未传播到 TTY 层

### 4.1 问题描述

`File::read()` 将 `self.nonblocking()` 传递给 `poll_io`，但 TTY 和 ldisc 层不感知此标志。

**调用链**:

```
File::read()
  → block_on(poll_io(File, IN, nonblocking, || {
      inner.read(dst)  ← nonblocking=true 传入 poll_io
    }))
    → Tty::read_at() [tty/mod.rs:86]
      → block_on(poll_io(JobControl, IN, false, || {  ← !!! false 硬编码 !!!
          ldisc.lock().read(buf)
        }))
        → ldisc.read() [ldisc.rs:328]
          → block_on(poll_io(WaitPollable, IN, false, || {  ← !!! false 硬编码 !!!
              buf_rx.pop_slice(buf)
            }))
```

**两个 false 硬编码问题**：

| 位置 | 代码 | 问题 |
|------|------|------|
| `Tty::read_at()`:90 | `IoEvents::IN, false,` | 应该传入 nonblocking 参数 |
| `ldisc.read()`:363 | `IoEvents::IN, false,` | 应该传入 nonblocking 参数 |

### 4.2 影响

即使设置了 `FIONBIO`（`File.nonblock = true`）：

1. **RX 路径**：`Tty::read_at()` 和 `ldisc.read()` 内部的 `block_on(poll_io(...))` 仍然使用 `false`（阻塞模式）
2. 内部 `block_on` 会**阻塞等待数据**，不会返回 `Err(WouldBlock)`
3. 外部 `File::read()` 的 `poll_io` 收到 `Ok(n)` 或一直等待，**不会因为 nonblocking 而提前返回**
4. **结论：FIONBIO 对 TTY 设备读取当前无效。**

### 4.3 write() 的情况

**文件**: `kernel/src/file/fs.rs:139-148`

```rust
fn write(&self, src: &mut IoSrc) -> AxResult<usize> {
    // ... 类似 read 但走 OUT
}
```

但写路径的 `AsyncUartWriter::write()` [device_ops.rs:17] 总是立即返回（push ring buffer），不阻塞。
所以 **FIONBIO 对 TX 路径没有影响**（TX 天然非阻塞）。

## 5. 其他 FileLike 实现的非阻塞支持

| 实现 | nonblocking | set_nonblocking | read 非阻塞行为 |
|------|------------|----------------|-----------------|
| `File` (VFS) | ✅ AtomicBool | ✅ 存储 flag | ✅ poll_io 传入 nonblocking |
| `Pipe` | ✅ AtomicBool | ✅ 存储 flag | ✅ pipe 空时返回 WouldBlock |
| `EventFd` | ✅ AtomicBool | ✅ 存储 flag | ✅ 无数据时返回 WouldBlock |
| `Socket` | ✅ 委托给 socket | ✅ 委托给 socket | ✅ 内核网络栈支持 |
| `PidFd` | ✅ AtomicBool | ✅ 存储 flag | ✅ 无状态变化时返回 WouldBlock |
| `Signalfd` | ✅ 字段 | ✅ 存储 flag | ✅ 无信号时返回 WouldBlock |
| **TTY (Tty<R,W>)** | ❌ 无字段 | ❌ 依托 DeviceOps | ❌ 硬编码 false |

TTY 设备是唯一**未实现**非阻塞支持的 FileLike 类型。

## 6. 实现方案

### 6.1 方案 A：TTY 层添加 nonblocking 标志（推荐）

**需要修改的文件**：

1. **`kernel/src/pseudofs/dev/tty/mod.rs`** — Tty 结构体添加 `nonblocking` 字段

```rust
pub struct Tty<R, W> {
    this: Weak<Self>,
    terminal: Arc<Terminal>,
    ldisc: Mutex<LineDiscipline<R, W>>,
    writer: W,
    is_ptm: bool,
    nonblocking: AtomicBool,    // ← 新增
}
```

2. **`Tty::read_at()`** — 传播 nonblocking 到内部调用

```rust
fn read_at(&self, buf: &mut [u8], _offset: u64) -> AxResult<usize> {
    let nb = self.nonblocking.load(Ordering::Acquire);
    block_on(poll_io(
        &self.terminal.job_control,
        IoEvents::IN,
        nb,                              // ← 使用 nonblocking 标志
        || {
            if self.is_ptm || self.terminal.job_control.current_in_foreground() {
                let mut ldisc = self.ldisc.lock();
                ldisc.set_nonblocking(nb);  // ← 传递到 ldisc
                ldisc.read(buf)
            } else {
                Err(AxError::WouldBlock)
            }
        },
    ))
}
```

3. **`ldisc.rs`** — Ldisc 添加 nonblocking 传播

```rust
impl<R: TtyRead, W: TtyWrite> LineDiscipline<R, W> {
    pub fn set_nonblocking(&mut self, nb: bool) {
        self.nonblocking = nb;
    }
}
```

并在 `ldisc.read()` 中使用 `self.nonblocking`：

```rust
pub fn read(&mut self, buf: &mut [u8]) -> AxResult<usize> {
    // ... 当前逻辑 ...
    block_on(poll_io(&pollable, IoEvents::IN, self.nonblocking, || {
        total_read += self.buf_rx.pop_slice(&mut buf[total_read..]);
        // ...
    }))
}
```

4. **`DeviceOps` trait 或 Tty 添加 `set_nonblocking` 接口**

问题在于 `Tty` 作为 `DeviceOps`，其 `read_at` 由 VFS 调用，但 `set_nonblocking` 需要从 File 层传递。

### 6.2 方案 B：File 层拦截，无需 TTY 修改（折衷）

在 `File::read()` 中直接检查 nonblocking：

```rust
fn read(&self, dst: &mut IoDst) -> AxResult<usize> {
    if self.nonblocking() {
        // 先尝试一次，如果 WouldBlock 立刻返回
        match inner.read(&mut *dst) {
            Err(AxError::WouldBlock) => return Err(AxError::WouldBlock),
            other => return other,
        }
    }
    // 原有 blocking 路径
    ...
}
```

**优点**：修改量小，不需要改 TTY/Ldisc
**缺点**：TTY 内部仍然可能阻塞（ldisc 的 block_on），不彻底

### 6.3 方案 C：通过 DeviceOps.flags() 传播（最少侵入）

`Tty` 的 `flags()` 方法返回 `NodeFlags::NON_CACHEABLE | NodeFlags::STREAM`。
但 `NodeFlags` 中是否有表示 nonblocking 的标志？

检查 `NodeFlags` 定义... 当前只有 `BLOCKING`、`NON_CACHEABLE`、`STREAM` 等。
可以通过修改 `flags()` 动态返回是否包含 `BLOCKING`，但 `File::is_blocking()` 检查的是设备类型，不是运行时标志。

**此方案不可行**。

## 7. 测试方案（O22）

### 7.1 测试目标

验证 `ioctl(FIONBIO)` 对 `/dev/console` 的非阻塞效果：
1. 设置非阻塞模式后，无数据时 `read()` 立即返回 `EAGAIN`/`EWOULDBLOCK`
2. 非阻塞模式下不会阻塞进程
3. `fcntl(fd, F_SETFL, O_NONBLOCK)` 等效

### 7.2 测试用例

```c
// tests/test_nonblock.c
#include <stdio.h>
#include <stdlib.h>
#include <fcntl.h>
#include <unistd.h>
#include <sys/ioctl.h>
#include <errno.h>
#include <string.h>

int main() {
    int fd = open("/dev/console", O_RDWR | O_NONBLOCK);
    if (fd < 0) {
        perror("open");
        return 1;
    }

    // 测试 1: O_NONBLOCK open 的 fd 读无数据应返回 EAGAIN
    char buf[16];
    ssize_t n = read(fd, buf, sizeof(buf));
    if (n == -1 && errno == EAGAIN) {
        printf("PASS: O_NONBLOCK read returns EAGAIN\n");
    } else {
        printf("FAIL: expected EAGAIN, got %zd (errno=%d)\n", n, errno);
    }

    close(fd);

    // 测试 2: 使用 ioctl FIONBIO 设置非阻塞
    fd = open("/dev/console", O_RDWR);
    int on = 1;
    if (ioctl(fd, FIONBIO, &on) < 0) {
        perror("ioctl FIONBIO");
        close(fd);
        return 1;
    }

    n = read(fd, buf, sizeof(buf));
    if (n == -1 && errno == EAGAIN) {
        printf("PASS: FIONBIO read returns EAGAIN\n");
    } else {
        printf("FAIL: expected EAGAIN, got %zd (errno=%d)\n", n, errno);
    }

    close(fd);

    // 测试 3: fcntl F_SETFL O_NONBLOCK
    fd = open("/dev/console", O_RDWR);
    int flags = fcntl(fd, F_GETFL, 0);
    if (fcntl(fd, F_SETFL, flags | O_NONBLOCK) < 0) {
        perror("fcntl F_SETFL");
        close(fd);
        return 1;
    }

    n = read(fd, buf, sizeof(buf));
    if (n == -1 && errno == EAGAIN) {
        printf("PASS: fcntl O_NONBLOCK read returns EAGAIN\n");
    } else {
        printf("FAIL: expected EAGAIN, got %zd (errno=%d)\n", n, errno);
    }

    close(fd);
    return 0;
}
```

### 7.3 预期行为（修复后）

| 测试 | 设置方式 | 无数据时 read() | 预期结果 |
|------|---------|----------------|---------|
| 1 | `open(O_NONBLOCK)` | 立即返回 `EAGAIN` | 当前可能阻塞 ❌ |
| 2 | `ioctl(FIONBIO)` | 立即返回 `EAGAIN` | 当前可能阻塞 ❌ |
| 3 | `fcntl(F_SETFL, O_NONBLOCK)` | 立即返回 `EAGAIN` | 当前可能阻塞 ❌ |
| 4 | blocking 模式 | 等待数据 | 正常 ✅ |
