### 1.2 Console 软件路径层次结构

```
用户态应用（shell、用户程序）
  ↓
/dev/console 设备节点
  ↓
N_TTY (Tty<Console, Console>)
  ├─ Terminal（行规则处理、缓冲区管理）
  │   ├─ rx_buf（接收环形缓冲区）
  │   └─ job_control（会话/进程组控制）
  └─ tty-reader copier（后台任务）
      ├─ InputReader（RX 数据搬运）
      ├─ Console.read() → axhal::console::read_bytes()
      ├─ Console.write() → axhal::console::write_bytes()
      └─ register_irq_waker(10, &waker)
          ↓
      axhal::console（外部 crate，不可修改）
          ├─ read_bytes(buf) → UART RBR
          ├─ write_bytes(buf) → UART THR（同步阻塞）
          └─ irq_num() → IRQ 10
              ↓
          axplat-riscv64-qemu-virt（外部 crate）
              ├─ UART 初始化（Config）
              ├─ MmioSerialPort（MMIO 访问）
              └─ write_bytes 忙等待循环
                  ↓
              UART 硬件（NS16550）
                  ├─ RBR 寄存器（RX 数据）
                  ├─ THR 寄存器（TX 数据）
                  └─ IRQ 10（PLIC）
```

```rust
fn new_n_tty() -> Arc<NTtyDriver> {
    Tty::new(
        Arc::default(),
        TtyConfig {
            reader: Console,                    // TtyRead 实现
            writer: Console,                    // TtyWrite 实现
            process_mode: if let Some(irq) = axhal::console::irq_num() {
                ProcessMode::External(Box::new(move |waker| register_irq_waker(irq, &waker)))
            } else {
                ProcessMode::Manual
            },
        },
    )
}
```

**关键步骤**：
1. 创建 Console struct（reader + writer）
2. 获取 IRQ 号（axhal::console::irq_num() → 10）
3. 注册 IRQ waker（register_irq_waker(10, &waker)）
4. 创建 Tty<Console, Console> 实例
5. 启动 tty-reader copier 任务（spawn_with_name("tty-reader")）

**bind_to 作用**（entry.rs:51）：
- 将 N_TTY 设置为 init 进程的 controlling terminal
- 设置 session 的 terminal
- 设置 foreground process group

## 4. Console 硬件访问路径

### 4.1 Console.read() 实现

**代码路径**（ntty.rs:15-19）：
```rust
impl TtyRead for Console {
    fn read(&mut self, buf: &mut [u8]) -> usize {
        axhal::console::read_bytes(buf)  // 外部 crate，不可修改
    }
}
```

**硬件操作**：
```
axhal::console::read_bytes(buf)
  → axplat-riscv64-qemu-virt console.rs
    → read RBR 寄存器（MMIO）
      → 返回 RX 数据
```

**调用时机**：
- tty-reader copier 任务循环调用（ldisc.rs:83）
- 不直接由用户 read() 调用

### 4.2 Console.write() 实现

**代码路径**（ntty.rs:20-24）：
```rust
impl TtyWrite for Console {
    fn write(&self, buf: &[u8]) {
        axhal::console::write_bytes(buf);  // 外部 crate，不可修改（同步阻塞！）
    }
}
```

**硬件操作**：
```
axhal::console::write_bytes(buf)
  → axplat-riscv64-qemu-virt console.rs
    → 逐字节写 THR，等待 THR_EMPTY（忙等待循环）
      → CPU 空转，阻塞时间取决于波特率
```

**调用时机**：
- 用户 write("/dev/console") → N_TTY.write_at() → Console.write()
- 内核日志（axlog）可能使用 Console 输出

### 4.3 Console 硬件访问总结

| 操作 | 软件路径 | 硬件操作 | 性能特征 |
|------|---------|---------|---------|
| **RX 路径** | Console.read() → axhal::console::read_bytes() | 读 RBR 寄存器 | 中断驱动，tty-reader 搬运 |
| **TX 路径** | Console.write() → axhal::console::write_bytes() | 写 THR + 忙等待 THR_EMPTY | **同步阻塞**，CPU 空转 |
| **IRQ 获取** | axhal::console::irq_num() | 返回 IRQ 10 | 配置查询 |

**关键约束**：
- axhal::console 是外部 crate，无法修改其同步阻塞实现
- TX 路径的性能瓶颈无法在 kernel 层解决
- 需要完全剔除 Console 才能实现异步 TX

## 5. Console IRQ 注册路径

### 5.1 register_irq_waker 使用

**注册位置**（ntty.rs:37-38）：
```rust
process_mode: if let Some(irq) = axhal::console::irq_num() {
    ProcessMode::External(Box::new(move |waker| register_irq_waker(irq, &waker)))
}
```

**IRQ waker 机制**：
```
UART RX 中断 (IRQ 10)
  → PLIC claim
    → axhal::irq_handler
      → IRQ_WAKERS[10].wake_by_ref()
        → tty-reader 任务唤醒
          → Console.read()
            → 读 RBR 寄存器
              → push rx_buf
                → 返回 Pending（等待下次中断）
```

### 5.2 tty-reader copier 任务

**任务启动**（推测，基于 Tty::new 流程）：
```rust
spawn_with_name("tty-reader", poll_fn(|cx| {
    // 1. 读 Console RX 数据
    let n = reader.read(&mut read_buf);

    // 2. 行规则处理（回显、信号检测）
    // ...

    // 3. push 到 rx_buf
    buf_tx.push(ReadBuf::new(&read_buf[..n]));

    // 4. 注册 IRQ waker
    register_irq_waker(irq, cx.waker());

    // 5. 返回 Pending
    Poll::Pending
}))
```

**关键特征**：
- tty-reader 是后台任务，持续读取 Console RX 数据
- 用户 read() 不直接读 Console，而是从 rx_buf pop
- IRQ 10 只唤醒 tty-reader，不直接唤醒用户任务

## 6. Console 用户态访问路径

### 6.1 read("/dev/console") 调用链

**完整调用链**：
```
用户态 read("/dev/console", buf, len)
  ↓ syscall read
  ↓ FD_TABLE lookup fd → File
  ↓ File.read()
  ↓ NodeOps.read_at()
  ↓ DeviceOps.read_at() (N_TTY 实现)
  ↓ Tty<R,W>.read_at()
  ↓ Terminal.read()
  ↓ rx_buf consumer pop()
  ↓ 返回数据给用户态
```

**关键发现**：
- 用户 read() 不直接读 Console 硬件
- 数据已在 tty-reader copier 任务中搬运到 rx_buf
- 用户 read() 是异步的（可 poll/select/epoll）

### 6.2 write("/dev/console") 调用链

**完整调用链**：
```
用户态 write("/dev/console", buf, len)
  ↓ syscall write
  ↓ FD_TABLE lookup fd → File
  ↓ File.write()
  ↓ NodeOps.write_at()
  ↓ DeviceOps.write_at() (N_TTY 实现)
  ↓ Tty<R,W>.write_at()
  ↓ Terminal.write()
  ↓ Console.write()
  ↓ axhal::console::write_bytes(buf)
  ↓ **同步阻塞**（CPU 空转）
  ↓ 返回写入字节数
```

**关键发现**：
- 用户 write() 直接调用 Console.write()
- Console.write() 使用同步阻塞 TX（axhal::console::write_bytes）
- **性能瓶颈**：用户 write() 会阻塞，无法异步化

## 9. 替代方案设计建议

### 9.1 UART 初始化替代方案

**方案**：使用 uart_16550 crate 本地初始化

**设计要点**：
```rust
// kernel/src/drivers/uart_init.rs（新建）
use uart_16550::{SerialPort, MmioBackend, BaudRate, FifoTriggerLevel, InterruptEnable};

pub fn init_uart_hardware() -> SerialPort<MmioBackend> {
    let uart = SerialPort::new_mmio(
        NonNull::new(0x10000000 as *mut u8).unwrap(),
        4,  // stride
    );

    uart.init(&Config {
        baud_rate: BaudRate::Baud115200,
        fifo_trigger_level: Some(FifoTriggerLevel::Fourteen),
        interrupts: InterruptEnable::DATA_READY,  // 使能 RX 中断
        ..Default::default()
    });

    uart
}
```

**关键问题**：
- 替代 axplat-riscv64-qemu-virt 的 UART 初始化
- 配置需要与 AsyncUart 兼容
- 需在内核启动早期调用

### 9.2 earlycon 内核日志方案

**方案**：简单的 polling TX 输出（不依赖 AsyncUart）

**设计要点**：
```rust
// kernel/src/drivers/earlycon.rs（新建）
use uart_16550::{SerialPort, MmioBackend};

pub fn earlycon_write(buf: &[u8]) {
    // 获取 UART 实例（全局静态）
    let uart = get_earlycon_uart();

    // 简单的 polling TX 输出（同步阻塞）
    for byte in buf {
        while !uart.lsr().contains(LSR::THR_EMPTY) {
            // 等待 TX FIFO 空（CPU 空转）
        }
        uart.try_send(*byte);
    }
}
```

**关键特征**：
- earlycon 不依赖 AsyncUart，独立于异步框架
- 启动早期可用（axruntime::init 之前）
- panic 时仍可用（调试安全机制）

### 9.3 AsyncUart 设备注册方案

## 12. 关键风险与预防

### 12.1 UART 初始化冲突风险

**风险**：AsyncUart 初始化可能与 axplat 的 UART 初始化冲突

**预防**：
- 在内核启动时**完全替代** axplat 的 UART 初始化
- 禁用 axplat 的 console.rs（无法修改外部 crate）
- 使用本地 uart_16550 crate 初始化 UART

### 12.2 earlycon 与 AsyncUart 共存风险

**风险**：earlycon（同步阻塞）与 AsyncUart TX copier 共享 UART 硬件

**预防**：
- earlycon 仅用于内核日志（紧急情况）
- 正常 TX 输出使用 AsyncUart TX copier
- 设计 UART 硬件独占机制（避免同时写 THR）

### 12.3 IRQ waker 注册冲突风险

**风险**：AsyncUart RX/TX copier 注册 IRQ 10 waker 时，可能与残留的 Console waker 冲突

**预防**：
- 完全剔除 Console 软件路径（移除所有 Console waker 注册）
- 使用 ISR + AtomicWaker 分发机制（区分 RX/TX 中断）
- 验证 IRQ waker 注册流程（确保无残留）

## 附录：Console 剔除决策摘要

**决策来源**：ADR-020（architecture.md）

**剔除原因**：
1. Console 与 AsyncUart 共享 UART 硬件导致数据竞争
2. Console TX 路径同步阻塞无法异步化
3. Console IRQ waker 与 AsyncUart 冲突（单一 waker 限制）
4. axhal::console 是外部 crate，无法修改其实现

**新方案**：
- 使用本地 uart_16550 crate + 自实现 UART 初始化
- 完全剔除 Console 软件路径
- AsyncUart 独占 UART 硬件

**关键约束**：
- axplat-riscv64-qemu-virt（外部 crate）无法修改
- axhal::console（外部 crate）无法修改
- UART 硬件独占是唯一可行方案
